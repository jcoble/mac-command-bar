## Scope and conclusion

This is a read-only trace of committed `HEAD` code. The two modified tracked files and existing untracked experiments were left untouched; receipts below come from `git show HEAD:<path>`. [verified: `git status --short`; `git show HEAD:tauri-svelte-preview/src/routes/next/+page.svelte:868-936`]

The switch has no single active-selection epoch. It starts several independent operations, and a later switch can begin before the earlier operation settles. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:868-936`]

## Exact switch sequence

1. `selectOwned` clears the draft flag, records `previous`, sets `rail.activeOwnedId`, and then awaits the previous session's draft flush. It snapshots the departing workspace synchronously, starts a best-effort terminal-projection stop, and awaits `setExtensionApiProbeWorkspace` for the arriving root. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:868-897`]
2. `shellPanels.sessionPicked()` is synchronous orchestration, but it fires the explorer and every visible root-scoped loader whose remembered root differs. It then repoints each shown editor/browser panel; browser is skipped in this loop. [verified: `tauri-svelte-preview/src/lib/shell/panelActivation.ts:197-245`]
3. On a real switch, `restoreWorkspace` starts a stored Git diff without awaiting it, restores browser/editor/conversation state, and may synchronously publish an eager editor-open request. The session-pick path can fire Problems; `restoreTabsFor` can immediately fire additional visibility activations, including Git History, source control, worktrees, stacks, editor, and browser activation. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:820-866,384-388`; `tauri-svelte-preview/src/routes/next/+page.svelte:346-376`; `tauri-svelte-preview/src/lib/shell/panelActivation.ts:197-245`]
4. The structured conversation branch awaits `loadConversationForRead` and draft loading in parallel. Conversation-surface effects independently start config, capabilities, and attachment reads when the active session changes. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:917-934`; `tauri-svelte-preview/src/lib/shell/components/ConversationSurface.svelte:216-257`]

For two sessions with the same root, explorer, Git, worktree, stacks, and Problems activations normally short-circuit on their root keys; the owned-ID-sensitive conversation and extension-probe paths still run. [verified: `tauri-svelte-preview/src/lib/shell/panelActivation.ts:197-204,248-283`; `tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:127-133`; `tauri-svelte-preview/src/lib/shell/git/gitService.ts:471-481`; `tauri-svelte-preview/src/lib/shell/worktrees/worktreeManagerService.ts:87-94`; `tauri-svelte-preview/src/lib/shell/stacks/stackService.ts:121-127`; `tauri-svelte-preview/src/lib/shell/problems/problemsService.ts:64-70`; `tauri-svelte-preview/src/routes/next/+page.svelte:894-897`]

## Async-operation ledger

### Draft persistence

- **Calls:** `flushConversationSessionDraft(previous)` is awaited before the panels move; `loadConversationSessionDraft(ownedId)` is awaited with the conversation snapshot. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:889-892,925-933`]
- **Stale guard:** persistence has a revision per `ownedId`; a load applies text only when the revision is unchanged. Writes are serialized per `ownedId`. [verified: `tauri-svelte-preview/src/lib/shell/conversation/conversationDraftPersistence.ts:12-17,40-55,70-82`]
- **Retention/overlap:** pending timers and write promises are deleted when their work settles; different session IDs have separate map entries. A pending promise can retain its text/closure until settlement. [verified: `tauri-svelte-preview/src/lib/shell/conversation/conversationDraftPersistence.ts:31-55,63-82`; assumed: pending-promise reachability while `tauri-svelte-preview/src/lib/shell/conversation/conversationDraftPersistence.ts:40-55` is awaiting]
- **Listeners:** none are installed per switch. [verified: `tauri-svelte-preview/src/lib/shell/conversation/conversationDraftPersistence.ts:12-82`]

### Extension API probe handoff

- **Call:** `setExtensionApiProbeWorkspace` awaits disposal of the previous terminal lease, disposes the SCM lease, replaces one global context, then notifies listeners. [verified: `tauri-svelte-preview/src/routes/next/+page.svelte:894-897`; `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeController.ts:87-100,135-160`]
- **Stale guard:** there is no request identity check around the await. A later call can be followed by an earlier call assigning the old context and notifying listeners. The separate `requireCurrent` guard protects later owner requests, not this setter. [verified: `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeController.ts:74-84,135-160`]
- **Retention/overlap:** the controller retains one context, one terminal lease, and one SCM lease; it has no per-root accumulation. The bridge's one global context listener starts an unawaited command for every context change, so rapid switches can queue copied context payloads until the command settles. [verified: `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeController.ts:52-58,103-116,135-160`; `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeBridge.ts:103-110`]
- **Listeners:** one bridge listener is registered once and removed at bridge disposal; no listener is registered per switch. [verified: `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeBridge.ts:85-115`]

### Explorer / Files root scan

- **Call:** `activateExplorer(root)` calls `void scanRoot(target)` for a new or failed root. Each scan awaits `listSourceFilesFromTauri`. [verified: `tauri-svelte-preview/src/lib/shell/shellPanels.ts:122-138`; `tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:86-133`]
- **Stale guard:** a monotonic `scanGeneration` is checked after success and in the catch path; the previous backend scan is cancelled best effort. A stale result returns before `setProjectSourceRecords` or `applyScanResult`. [verified: `tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:59-77,90-116`]
- **Retention/overlap:** the visible explorer list is one replaced array. The separate `recordsByRoot` map retains every completed root scan and normal switches deliberately do not clear it; only a failed root or the explicit test/support clear removes an entry. Different roots therefore accumulate. [verified: `tauri-svelte-preview/src/lib/shell/explorer/explorerStore.svelte.ts:77-126`; `tauri-svelte-preview/src/lib/shell/projectSourceIndex.ts:10-42`]
- **Bytes:** the retained record-array size is assumed proportional to the scanned file count and metadata; the source proves the holder, not its size. [assumed: `tauri-svelte-preview/src/lib/shell/projectSourceIndex.ts:16-24`]
- **Listeners:** FilesPanel starts an async filesystem watcher only while visible and listed; cleanup marks the setup abandoned, stops a late-created watcher, and removes the active watcher. [verified: `tauri-svelte-preview/src/lib/shell/panels/files/FilesPanel.svelte:142-188`]
