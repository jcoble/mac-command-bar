Independent provider adapter updates

Assembly checks for a signed adapter bundle once at launch. Settings offers the existing explicit install-and-restart action. No app installer is downloaded and no idle timer is added.

Confirmed gaps

  • The old updater follows GitHub’s latest release, currently a remote backend release without provider assets.
  • Provider publishing was coupled to the app release workflow.
  • Published Codex 1.11.0 and Claude 0.76.0 trail upstream 1.13.1 and 0.81.2.
  • The registry uses the verified installed provider bundle ahead of development wrappers, including on relaunch. Native update proof will use this same production installer path.

Scope

Keep the existing manifest, signature, streamed payload verification, atomic activation, and Settings controls. Add a dedicated provider release workflow and endpoint, launch-time checking, bounded metadata reads, and rejection of bundle downgrades. Existing Antigravity covers Gemini models. Model availability also depends on the vendor CLI/account; an adapter update alone is not proof that its catalog changed.

Validation

Run provider updater Rust logic tests and Svelte checks. Verify both architectures build and signed manifests publish, then exercise download, hash verification, activation and relaunch in a packaged app. TSK-936 stays Doing until this end-to-end acceptance and clean-machine provider discovery pass.
