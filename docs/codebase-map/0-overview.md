# Assembly: current application overview

## What the application is

Assembly is a macOS desktop workbench for running and supervising coding-agent sessions beside the project they are changing. Its current product identity is `Assembly`; the same name is supplied to terminal children and language servers, and the native startup failure text is `failed to run Assembly` (`tauri-svelte-preview/src-tauri/src/product_identity.rs:1-4`). The active workbench is the `/next` Svelte route inside a Tauri application. It combines owned Codex, Claude, and Antigravity conversations with terminals, source browsing and editing, Git, native browser tabs, diagnostics, worktrees, resource controls, provider usage, and workflow runs (`tauri-svelte-preview/src/routes/next/+page.svelte:1-10`; `tauri-svelte-preview/src-tauri/src/main.rs:5681-5905`).

The person running the application works in one desktop window. The left column contains sessions, the center contains the selected Session, Editor, or Diff surface, the right column contains Files, Source Control, Worktrees, Run, Context, Agents, Browser, and History, and an optional bottom dock contains Problems. A full-width utility strip opens Settings, Resources, and Usage (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:28-88`; `tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:19-44`; `tauri-svelte-preview/src/lib/shell/components/UtilityStrip.svelte:1-18`).

An Assembly-owned conversation is not only a terminal process. The Rust runtime creates or resumes an Agent Client Protocol session, journals its canonical events in SQLite, stops the adapter process after the turn becomes quiescent, and resumes the provider-native session for the next message. Externally discovered sessions remain distinct: the application scans provider transcript stores, can adopt a scanned session as a terminal projection, and can import and resume eligible transcript history as a structured Assembly session (`tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:257-267,686-1018,3621-3632`; `tauri-svelte-preview/src/lib/shell/ownedSessions.ts:201-233`; `tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:133-177`).

The application keeps durable session identity and conversation history in native stores while keeping most workbench presentation state in browser storage or process memory. SQLite is authoritative for owned sessions; the session rail, conversation stores, panel stores, and Session Library are projections of that authority or of current native scans (`core/src/session_store.rs:64-117,119-254`; `tauri-svelte-preview/src/lib/shell/stores/sessionRailStore.svelte.ts:1-23`; `tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:1-8`).

## Architecture at a high level

### Processes and communication

The application has four process roles:

1. The Tauri webview renders the Svelte workbench, owns route and panel state, invokes named native commands, and listens for native events such as `agent-conversation-event`, `terminal_output`, `source-lsp-status-changed`, browser events, and `workflow-run-updated` (`tauri-svelte-preview/src-tauri/src/main.rs:5737-5905`; `tauri-svelte-preview/src-tauri/src/main.rs:71-72,1660-1662,5722-5734`; `tauri-svelte-preview/src-tauri/src/browser.rs:36-39`).
2. The Rust Tauri process owns the native registries for agent conversations, pseudo-terminals, language servers, browser child views, source scans, resources, usage history, and workflows. Startup constructs and manages those registries before exposing the command handler (`tauri-svelte-preview/src-tauri/src/main.rs:5681-5735`).
3. Agent adapters are bundled sidecar processes speaking newline-delimited Agent Client Protocol JSON-RPC over standard input and output. They run in marked process groups, can be shared by providers that advertise multi-session support, and are detached after quiescent work (`tauri-svelte-preview/src-tauri/src/agent_conversation/providers/process.rs:118-257`; `tauri-svelte-preview/src-tauri/src/agent_conversation/providers/acp_client.rs:26-149,367-435`; `tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:677-852,3621-3632`).
4. Terminal shells and language servers are child processes owned by native registries. Terminal children run as login shells in pseudo-terminals; language servers are keyed by language and canonical workspace root, with a separate native Roslyn endpoint used by Monaco for C# (`tauri-svelte-preview/src-tauri/src/terminal.rs:80-198,445-551`; `tauri-svelte-preview/src-tauri/src/lsp.rs:1038-1283,1588-1774`).

The front end never reaches those processes directly. It invokes Tauri commands through typed service modules. Native events feed store reducers, and page-owned navigation handlers connect otherwise independent surfaces without importing one panel into another (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:434-747`; `tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:1-15,89-159`).

### State and storage

Durable native state is split by purpose. `sessions.db` stores owned sessions, conversation events, drafts, annotations, attachment metadata, per-session workspace snapshots, and global Assembly settings; `usage-history.sqlite3` stores source cursors, usage events, and database-computed rollups; the orchestration ledger is append-only JSONL; attachment images and browser profiles are files below the application-data directory (`core/src/session_store.rs:155-248,586-657`; `tauri-svelte-preview/src-tauri/src/usage_history.rs:110-119`; `tauri-svelte-preview/src-tauri/src/orchestration.rs:9-14,347-471`; `tauri-svelte-preview/src-tauri/src/agent_conversation/attachments.rs:118-145`; `tauri-svelte-preview/src-tauri/src/browser.rs:1851-1936`).

Browser storage still holds the outer Gridview, center and side-pane layout payloads, general settings, custom project roots, and per-project language-intelligence mode. Session workspace state, session-column fold state, My Work choices and row order, browser restoration metadata, and Usage display direction instead belong to `sessions.db` (`tauri-svelte-preview/src/lib/shell/layout/layoutStorage.ts:17-149`; `tauri-svelte-preview/src/lib/settingsStore.svelte.ts:100-228`; `tauri-svelte-preview/src/lib/shell/newSession/projectRootsStore.svelte.ts:102-151`; `tauri-svelte-preview/src/lib/shell/editor/languageIntelligenceMode.ts:1-36`; `tauri-svelte-preview/src/lib/tauriSource.ts:1547-1582`). Reference counts have a separate IndexedDB store named `mcb-code-intelligence-v2` with object store `reference-counts` (`tauri-svelte-preview/src/lib/shell/editor/referenceCountPersistence.ts:1-15`).

Process memory holds the current overlays: live agent transports and requests, pseudo-terminal handles and scrollback, language-server slots, browser registry state, resource samples, Svelte stores, and one active session workspace projection (`tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:104-142,257-267`; `tauri-svelte-preview/src-tauri/src/terminal.rs:80-91`; `tauri-svelte-preview/src/routes/next/+page.svelte:195,754-802,866-908`).

## Application startup, shell, layout, and navigation

### Startup ownership

`src/routes/next/+page.svelte` is the workbench orchestrator. Its opening contract assigns launch input/output to terminal sessions, leaves each panel responsible for its own loading, and reconciles stored sessions before it hydrates the rail (`tauri-svelte-preview/src/routes/next/+page.svelte:1-10`). `ShellFrame.svelte` constructs the outer Gridview and center Dockview, while `RightPanel.svelte`, `DockPanel.svelte`, `UtilityStrip.svelte`, and `ShellOverlays.svelte` mount the surrounding surfaces (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:25-66,93-163`; `tauri-svelte-preview/src/lib/shell/components/RightPanel.svelte:30-120`; `tauri-svelte-preview/src/lib/shell/components/ShellOverlays.svelte:30-165`).

The route first mounts the frame and tool column, adds the route-scoped document class, applies the stored theme, installs drag-and-drop suppression and event subscriptions, and applies the stored Problems location. It then creates and attaches the terminal service, lists live pseudo-terminals, lists stored conversation sessions, reconciles those session rows with the live terminals, hydrates the rail, prunes per-session workspace snapshots, reattaches eligible terminals, and scans provider sessions (`tauri-svelte-preview/src/routes/next/+page.svelte:1419-1549`). The route opens session-panel loading only in the final startup block, after reattachment has completed (`tauri-svelte-preview/src/routes/next/+page.svelte:1538-1549`).

The session database is the startup authority. Commit `65c2353` removed the former empty-database import from webview localStorage because WebKit writes localStorage lazily; deleted sessions had returned after quitting, and one failed migration aborted shell startup (`tauri-svelte-preview/src/routes/next/+page.svelte:1486-1502`; commit `65c2353`).

The shell keeps layout construction errors separate from rail errors. The scan clears `rail.error`, so Dockview and Gridview failures live in `layoutError` and render through a fixed `role="alert"` strip above pane stacking contexts. Awaited startup, scan, adoption, and session-operation failures use `rail.error`; that rail message is included only while Session is the center surface (`tauri-svelte-preview/src/routes/next/+page.svelte:310-313,680-706,1764-1788`; `tauri-svelte-preview/src/lib/shell/components/ShellOverlays.svelte:141-160`; commits `ef9de6a`, `65c2353`). Settings import and command-palette failures have their own local alert surfaces (`tauri-svelte-preview/src/lib/shell/components/SettingsHost.svelte:51-100`; `tauri-svelte-preview/src/lib/shell/components/PalettePanel.svelte:76-84,165-184`).

On `pagehide` and route destruction, the page captures the current workspace, releases its registered handlers and event listeners, disposes the terminal service, clears route maps and theme appliers, and removes the document class (`tauri-svelte-preview/src/routes/next/+page.svelte:1553-1584`).

### Gridview, Dockview, and panel lifetime

The outer Gridview has `sessions`, `center`, and `tools` regions plus an optional bottom `dock`. Its current limits are 220-560 pixels for sessions, 240-960 pixels for tools, a 420-pixel center minimum, a 180-pixel dock minimum, and a 52-pixel folded session column (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:28-88`). It writes a non-zero serialized layout after a 250-millisecond debounce and restores it only when the stored panel identifiers exactly match the current roster (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:355-419`; `tauri-svelte-preview/src/lib/shell/layout/layoutStorage.ts:66-149`).

The center is one Dockview group with permanent `session`, `editor`, and `diff` panels. Svelte content is teleported into Dockview hosts and returned to a `display:none` parking stage when detached. Removed roster panels are re-added on a later macrotask because Dockview emits removal before disposing the host (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:76-160,162-239`; `tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:185-208`). Commit `ef9de6a` records both failures that shaped this arrangement: closing a center tab stranded its live terminal, and a one-pixel parking box resized xterm to a 2-by-1 grid (commit `ef9de6a`).

`ShellFrame` lays out the parent Gridview before creating or restoring the center Dockview. Commit `1c5aed6` records that restoring while the parent was 0 by 0 corrupted Diff and Monaco bounds (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:93-155`; commit `1c5aed6`). Center persistence includes serialized layout data, but current restore uses only the saved active panel and does not replay the saved Dockview tree (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:314-357`).

The session fold preference and Gridview width are separate records. The page reasserts expanded width limits and repairs only an undersized restored width. Commit `5bfc336` records that a reload between the immediate fold write and debounced grid write had restored expanded markup in a 52-pixel locked column (`tauri-svelte-preview/src/routes/next/+page.svelte:575-638,1729-1755`; commit `5bfc336`).

All eight right-panel bodies remain mounted and `RightPanel.svelte` changes their display state, preserving local scroll and filter state (`tauri-svelte-preview/src/lib/shell/components/RightPanel.svelte:1-16,54-82`). Data access remains visibility-driven through `panelActivation.ts`: a visible surface and selected project cause activation, repeat activation for the same folder is skipped, and Problems reads only on explicit Refresh (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:151-297`). Commit `a47f897` records that earlier panel implementations existed but were mounted nowhere and establishes the current visible-only loading boundary (commit `a47f897`).

The generic Paneview stack, side-pane registry, action-surface reducer, and older sidebar-view keys remain in the source tree. The current `/next` route does not mount the generic Paneview stack, the action-surface store identifies the floating action button as its only mounted consumer, and the older left/session pane keys are deliberately not read (`tauri-svelte-preview/src/lib/shell/layout/paneStack.ts:76-228,244-567`; `tauri-svelte-preview/src/lib/shell/overlay/actionSurfaceStore.svelte.ts:1-16`; `tauri-svelte-preview/src/lib/shell/layout/sidebarViews.ts:11-23,61-114`).

### Navigation, commands, settings, and themes

`workbenchNavigation.ts` is the process-wide navigation seam. The page registers handlers for showing center and right surfaces, opening a diff or URL, focusing or sending to a composer, and starting a session. Calls made before registration or after cleanup are no-ops (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:46-159`; `tauri-svelte-preview/scripts/workbenchNavigation.test.ts:26-49`). Opening a file publishes an `OpenFileRequest` before showing Editor; opening a URL shows Browser before navigation; composer operations select the session and then show Session (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:101-159`). The module exists so panels do not import one another (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:1-15`).

The command registry supplies replaceable command sources, duplicate-identifier handling, search, disabled-row handling, and awaited execution. `shellCommands.ts` registers navigation, session, editor, browser, source-control, worktree, stack, Playwright, and Problems commands (`tauri-svelte-preview/src/lib/shell/palette/commandRegistry.ts:19-166`; `tauri-svelte-preview/src/lib/shell/shellCommands.ts:44-201`). Center controls are floating Session, Editor, and Diff pills; commit `1574198` records the removal of the former top strip and the one-second post-switch hold implemented by `CenterCornerTabs.svelte` (`tauri-svelte-preview/src/lib/shell/components/CenterCornerTabs.svelte:50-116`; commit `1574198`).

Settings is imported only on first open. The dialog contains appearance, editor, terminal, general, Problems-location, and C# language-server controls backed by one `mac-command-bar.settings` localStorage value (`tauri-svelte-preview/src/lib/shell/components/SettingsHost.svelte:25-103`; `tauri-svelte-preview/src/lib/settingsStore.svelte.ts:21-132,141-213`). `SettingsSelect.svelte` uses `svelte-select`; its source comment records that the Bits UI select opened on pointerdown and dismissed on the same pointerup inside the WebView (`tauri-svelte-preview/src/lib/shell/components/SettingsSelect.svelte:1-7`). Editor ligatures and terminal cursor blink are currently local dialog values because the settings store has no fields for them (`tauri-svelte-preview/src/lib/shell/components/SettingsDialog.svelte:293-296`).

Themes are complete records containing shell tokens, Monaco colors and rules, and terminal palettes. Houston is the default and Dracula is the second registered theme; unknown identifiers resolve to Houston (`tauri-svelte-preview/src/lib/shell/themes/themeRegistry.ts:31-150,153-539`). The theme service paints both `document.documentElement` and `.next-shell`, then calls registered Monaco and terminal repaint functions. Commit `3e2817f` records that the root is also required for portaled menus and dialogs and that the unified record replaced settings names that did not repaint the three surfaces (`tauri-svelte-preview/src/lib/shell/themes/themeService.ts:81-190`; commit `3e2817f`). Both themes currently carry the terminal factory's established Dracula palette, so Houston does not change an existing terminal palette (`tauri-svelte-preview/src/lib/shell/themes/themeRegistry.ts:187-505`; commit `de71598`).

The `/next` styles are route-scoped. `nextTokens.css` applies tokens to `.next-shell` and `:root.next-shell-document`, while `next.css` maps them to component variables without applying the older shell's global baseline (`tauri-svelte-preview/src/lib/shell/styles/nextTokens.css:1-42`; `tauri-svelte-preview/src/lib/shell/styles/next.css:1-59,124-242`). Commit `ccd3cc1` records that WebKit spent seconds invalidating relational `:has()` selectors during bulk transcript insertion; the current route and styles use explicit state classes instead (`tauri-svelte-preview/src/lib/shell/styles/nextTokens.css:1-42`; commit `ccd3cc1`).

### Regression-sensitive shell contracts

- Session identity is loaded from SQLite before rail hydration; the removed localStorage session import is not part of startup (`tauri-svelte-preview/src/routes/next/+page.svelte:1486-1510`; commit `65c2353`).
- Parent layout occurs before center Dockview construction, and hidden teleported content is not measurable (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:93-155,185-208`; commits `1c5aed6`, `ef9de6a`).
- Center panel identifiers remain `session`, `editor`, and `diff`; right identifiers remain `files`, `source-control`, `worktrees`, `run`, `context`, `agents`, `browser`, and `history` (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:19-44`).
- Panel reads are gated by visibility and startup readiness rather than component lifetime (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:8-53,206-297`; commit `a47f897`).
- Theme repaint covers shell CSS, Monaco, terminal, and portaled overlays through one registered theme (`tauri-svelte-preview/src/lib/shell/themes/themeService.ts:1-29,81-190`; commit `3e2817f`).

## Session identity, rail, History, and session creation

### Owned and scanned identities

An owned session is keyed by an Assembly-minted `ownedId`. Provider-native session identifiers are carried for resume and transcript access but are not primary keys because a provider can mint a different identifier during resume (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:1-7`). The durable record includes provider, model, project and working directory, native and pseudo-terminal identifiers, lifecycle and runtime fields, timestamps, branch/task/pull-request metadata, bounded transcript count and preview, and rail metadata (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:15-123`).

Origins remain explicit. `origin: 'app'` is an app-created structured Agent Client Protocol session; `origin: 'external'` is a scanned provider session adopted as a terminal projection. `source: 'fresh' | 'scanned'` records how the row was created (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:48-63,201-270`). Commit `b91e29d` records this structured-versus-terminal ownership split, and reload reconciliation preserves it (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:440-481`; commit `b91e29d`).

The scanner supplies available provider sessions without an `ownedId`. They carry provider, native identifier, project, title or description, model, activity, bounded count and preview, resume commands, and transcript path (`tauri-svelte-preview/src/lib/shell/stores/sessionRailStore.svelte.ts:11-23`; `tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:187-213`). The core scanner reads bounded Codex, Claude, and cmux sources, excludes Codex subagent paths before its budget, merges by provider and native identifier, and reports message counts as floors because only bounded head/tail windows are read (`core/src/scanners/sessions.rs:37-94,189-334`). Commit `9bc3c27` records that count and preview reuse the bytes already read for titles rather than widening the file budget (commit `9bc3c27`).

The Session Library is a derived projection, not another authority. Owned keys are `owned:<ownedId>`; provider keys encode provider, native session identifier, and canonical working directory. Titles are absent from identity. Owned rows win compound-identity collisions, while a matching provider record can fill a missing transcript path (`tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:100-134,216-263`). The current bounded projection leaves `firstPrompt` null, synthesizes at most one latest-turn preview, and carries no subagent rows (`tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:31-68,151-157`).

### Rail shelves, presence, and row behavior

Working, Done, and Settled are user classifications. No `completedAt` means Working, `completedAt` without `settledAt` means Done, and `settledAt` means Settled (`tauri-svelte-preview/src/lib/shell/components/myWorkViewOptions.ts:38-44`; `tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:136-145`). Terminal exit does not write `completedAt`, and a completed session can still have a running terminal (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:66-84`; `tauri-svelte-preview/src/lib/shell/components/sessions/sessionCardModel.ts:42-67`). Commit `81175bd` records that Done is a user answer and that removal remains a separate confirmed action; commit `8f4f127` adds Settled as an independent stamp (commits `81175bd`, `8f4f127`).

Runtime presence is separate from the shelf. Active runtime states appear working; approvals and input requests contribute Needs you; background is open but not selected; exited is stopped (`tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte:84-210`). Presence history derives working, needs-attention, idle, and disconnected from conversation events and stores the viewed-session acknowledgement. Notifications record presence first, then emit at most one best-effort system notification only when the session needs attention and is not both viewed and focused (`tauri-svelte-preview/src/lib/shell/conversation/sessionPresence.ts:69-183,206-234`; `tauri-svelte-preview/src/lib/shell/conversation/sessionNotifications.ts:40-77,131-151`).

The rail is one scroll area with grouped rows, row-local hover actions, filtering, grouping, sorting, section collapse, and drag ordering within a group (`tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:1-9,51-183`; `tauri-svelte-preview/src/lib/shell/components/SessionsColumn.svelte:48-166`). Commit `a5d7ace` records the one-list rail and bounded aging clock; current rows use `content-visibility: auto`, and the working indicator exists only while a row is on screen (`tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:252-263`; `tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte:630-653`; commit `a5d7ace`). The current rail renders owned-session groups; History groups initially show 25 rows (`tauri-svelte-preview/src/lib/shell/components/myWorkViewOptions.ts:113-142`; `tauri-svelte-preview/src/lib/shell/history/sessionHistoryViewModel.ts:9-15`).

The row menu exposes implemented actions and leaves Rename, Move to project, Continue in new session, and Reveal in Finder disabled because corresponding commands are absent (`tauri-svelte-preview/src/lib/shell/components/sessionRowMenu.ts:48-103`). Row jumps select the session before switching to Session, Editor, or Source Control (`tauri-svelte-preview/src/lib/shell/components/sessionRowJump.ts:40-90`).

### History and transcript resume

History builds from both owned and available rail records, groups canonical paths into projects and worktrees, filters across bounded content and metadata, and sorts by activity (`tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:73-88`; `tauri-svelte-preview/src/lib/shell/history/sessionHistoryViewModel.ts:121-324`). It mounts only while visible. Without search, each checkout renders 25 rows and reveals 25 more per request; its age clock also runs only while visible. Commit `71d3d2c` records that the previous hidden panel mounted about 4,000 rows during startup and caused this bound (`tauri-svelte-preview/src/lib/shell/history/sessionHistoryViewModel.ts:57-64`; `tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:255-262`; commit `71d3d2c`).

History actions resume an eligible record as an Assembly session, view or open its log, copy resume data, open the working directory, copy identifiers, or delete an owned row (`tauri-svelte-preview/src/lib/shell/panels/history/sessionHistoryActions.ts:17-150`). Delete removes the application row and leaves the provider transcript file (`tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:355-370`). Resume requires a supported provider, native identifier, transcript path, and canonical working directory. It imports the transcript into the conversation store, adds the resulting stored row to the rail, selects Session, and starts structured resume mode; it does not start a command-line process (`tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:133-177`). Commit `92e5ee5` records that earlier separate resume paths did not produce a sendable session and were replaced by this import-plus-resume action (commit `92e5ee5`).

Commit `7dba43c` records the original transcript-opening action and normalized provider request. The current action roster uses that request for resume and uses View Log for direct file opening; the backwards-growing import wrapper exists but has no current History caller (`tauri-svelte-preview/src/lib/shell/panels/history/sessionHistoryActions.ts:85-99`; commit `7dba43c`). Commit `06147a5` records that imported projections previously failed to decode and had no live listing entry; imports now write complete events and session rows before recovery (`tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:150-172`; commit `06147a5`).

### Starting a new structured session

The plus action opens `DraftSessionSurface` in the Session center panel. Prompt, provider, model, effort, access, project, checkout, branch, and worktree-creation choice remain a draft; no session exists until the first send (`tauri-svelte-preview/src/lib/shell/newSession/DraftSessionSurface.svelte:1-13,61-108`; `tauri-svelte-preview/src/lib/shell/newSession/threadStartFlow.ts:36-64`). Provider choices are Codex, Claude, and Antigravity. Project choices merge built-in roots, persisted custom roots, and roots currently represented on the rail (`tauri-svelte-preview/src/lib/shell/newSession/threadStartFlow.ts:76-109,169-214`; `tauri-svelte-preview/src/lib/shell/newSession/projectRootsStore.svelte.ts:75-100`).

The first send requires a prompt, absolute project and working-directory paths, and a branch. New-worktree creation is currently rejected, so the request selects an existing checkout (`tauri-svelte-preview/src/lib/shell/newSession/threadStartFlow.ts:291-317`). The route then creates an app-owned structured row, selects Session and Files, sends the first prompt with its model, effort, and approval policy, persists metadata, and marks the runtime ready. Failure changes the row to exited, stopped, failed, and retains the error (`tauri-svelte-preview/src/routes/next/+page.svelte:1070-1137`).

An older pure terminal-launch catalog remains in `newSessionFlow.ts`. It covers Codex, Claude, and Terminal, previews a `cd` plus one command line, and also contains an explicit no-worktree-creation rule (`tauri-svelte-preview/src/lib/shell/newSession/newSessionFlow.ts:24-88,128-143,200-243`).

The core source module previews UTF-8 C#, TypeScript, JavaScript, and JSX under a 512 KiB ceiling, parses supported syntax with tree-sitter, and returns text plus syntax-role spans (`core/src/source.rs:12-22,105-141`). Directory scans validate a root, clamp results to 25,000, skip configured directories, filter by query, and return sorted records, truncation, and diagnostics (`core/src/source.rs:143-192,258-390`). Native wrappers run heavy work through `spawn_blocking` and can emit `source_scan_progress` (`tauri-svelte-preview/src-tauri/src/main.rs:613-681`).

The explorer is inert until Files becomes active or Refresh is selected. A superseding scan cancels the prior native walk, and results replace the raw store array; there is no scan cache (`tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:1-25,47-114`; `tauri-svelte-preview/src/lib/shell/explorer/explorerStore.svelte.ts:34-120`). The source comment records that uncancelled walks had run in parallel and an earlier uncapped localStorage cache failed on large repositories (`tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:13-24`). Files builds a sorted folder tree, keeps ignored records dimmed, opens matching folders during filter, virtualizes visible rows, and sends selected files through the editor navigation seam (`tauri-svelte-preview/src/lib/shell/panels/files/fileTreeModel.ts:1-91`; `tauri-svelte-preview/src/lib/shell/explorer/explorerTree.ts:27-110`; `tauri-svelte-preview/src/lib/shell/panels/files/FilesPanel.svelte:67-125`).

### Editor and reference counts

The editor store holds open paths, active file, preview/reveal/loading/error state in memory. Per-session workspace capture persists path and scroll information, while up to three recent sessions retain already-read tab contents in memory (`tauri-svelte-preview/src/lib/shell/editor/editorStore.svelte.ts:1-17,35-52`; `tauri-svelte-preview/src/lib/shell/sessionWorkspaces.ts:373-507`). Commit `064eb57` records that session switches previously reread every file and establishes the three-session least-recently-used retention cap (commit `064eb57`).

C# file access goes through a Monaco bridge with Tauri reads and guarded writes. Monaco workers use Vite worker URLs (`tauri-svelte-preview/src/lib/shell/editor/csharpFileSystem.ts:1-55`; `tauri-svelte-preview/src/lib/shell/editor/monacoWorkers.ts:18-52`). `sourceIntelligence.ts` selects native Roslyn as authoritative for C# and uses browser scanning only as plain-text fallback (`tauri-svelte-preview/src/lib/shell/editor/sourceIntelligence.ts:1-39`).

Reference counting batches symbols into one project pass. The optimized `mcb-core` implementation has a 4 MiB per-file ceiling distinct from the 512 KiB preview ceiling. Commit `6acb2db` records that a 660 KiB file made every project total a floor under the preview limit, and that one full-project read per symbol—about 120 concurrent reads—froze the editor (`core/src/reference_counts.rs:1-10,20-29,88-233`; `tauri-svelte-preview/src-tauri/src/main.rs:813-820`; commit `6acb2db`). Results report whether a deadline or file ceiling made them approximate; zero means no match in the scanned set (`tauri-svelte-preview/src-tauri/src/main.rs:74-219`).

### Language servers and native C#

Language-intelligence mode is stored per project. Read is the default and does not start a server; Full allows startup on file open, and leaving Full stops that workspace's language-server processes (`tauri-svelte-preview/src-tauri/src/lsp.rs:68-128`; `tauri-svelte-preview/src/lib/shell/editor/languageIntelligenceMode.ts:1-24`). A separate process-wide C# switch can stop C# servers while leaving source scan and reference count available (`tauri-svelte-preview/src-tauri/src/main.rs:898-1009`).

Configured servers are Roslyn for C#, TypeScript language server for TypeScript, TSX, JavaScript, and JSX, rust-analyzer for Rust, and svelteserver for Svelte. Python and Go have no configured server and return an unavailable reason (`tauri-svelte-preview/src-tauri/src/lsp.rs:4516-4555,5273-5293`). Executable discovery combines the application node bin, cached login-shell path, inherited path, Cargo, .NET tools, local-bin, nvm, Homebrew, and system paths because Finder-launched applications receive a narrower environment (`tauri-svelte-preview/src-tauri/src/lsp.rs:4558-4746`; commit `561747e`).

Each language and canonical root has a slot, with at most five workspaces per language. A reader task routes concurrent framed Language Server Protocol responses by request identifier, sends cancellation after timeout, and keeps server logs and diagnostics (`tauri-svelte-preview/src-tauri/src/lsp.rs:27-66,1038-1448,1588-1601`). Commit `bd0f9d2` records the replacement of `csharp-ls` with Roslyn and the bounded per-workspace registry (commits `6acb2db`, `bd0f9d2`). Existing servers are warmed on project switch, but unused languages are not spawned (`tauri-svelte-preview/src-tauri/src/lsp.rs:2510-2568`; commit `99fba29`).

The native C# path coalesces concurrent ensures into one canonical-root endpoint and exposes it to Monaco; CodeLens refresh is wired through `csharpLanguageClient.ts` (`tauri-svelte-preview/src-tauri/src/lsp.rs:1680-1774,2172-2303,2435-2620`; `tauri-svelte-preview/src/lib/shell/editor/csharpLanguageClient.ts:1-52`). The recorded serial test receipt for concurrent native C# ensure reaches the native-bridge error `Operation not permitted (os error 1)` before its same-endpoint assertions (`tauri-svelte-preview/src-tauri/src/lsp.rs:6713-6743`; `docs/superpowers/evidence/tsk-808/a9-rust-review-receipt.md:57-68`).

The extension API probe is a bounded internal fixture. It carries owned identifier, generation, canonical roots, and active root, rejects stale requests when those differ, and exposes terminal and source-control adapters through a registered command bridge (`tauri-svelte-preview/src/lib/shell/editor/fixtures/mcbExtensionApiProbe.ts:72-99`; `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeController.ts:74-100`; `tauri-svelte-preview/src/lib/shell/editor/extensionApiProbeBridge.ts:85-100`).

### Problems

Problems loads only on activation or Refresh. It first asks for whole-project diagnostics and, when an older desktop build rejects that command, falls back to open language-intelligent files. The result records which route supplied it and how many files were read, so the fallback is not presented as a clean whole project (`tauri-svelte-preview/src/lib/shell/problems/problemsService.ts:1-27,87-166`). ### Regression-sensitive source contracts

- Full language intelligence is opt-in per project; read mode does not start idle servers (`tauri-svelte-preview/src-tauri/src/lsp.rs:68-128`).
- Reference counts use one optimized multi-symbol pass and a 4 MiB file ceiling (`core/src/reference_counts.rs:1-10,20-29,88-233`; commit `6acb2db`).
- Language-server requests are concurrently routed by request identifier rather than serialized behind a slow request (`tauri-svelte-preview/src-tauri/src/lsp.rs:773-799,1140-1283`; commit `6acb2db`).
- Existing servers warm on project switch; unused languages remain unstarted (`tauri-svelte-preview/src-tauri/src/lsp.rs:2510-2568`; commit `99fba29`).
- Problems distinguishes whole-project diagnostics from the open-file fallback (`tauri-svelte-preview/src/lib/shell/problems/problemsService.ts:14-27,87-166`).

## Resource, process, and disk management

## Cross-application invariants

These statements are true across the current application and join multiple subsystems.

1. **Assembly-owned identity is `ownedId`.** Provider identifiers, terminal identifiers, transcript paths, titles, and working directories are attributes used for resume or display, not replacements for the durable owned key (`tauri-svelte-preview/src/lib/shell/ownedSessions.ts:1-7`; `tauri-svelte-preview/src-tauri/src/agent_conversation/protocol.rs:287-344`).
2. **SQLite is the owned-session and conversation authority.** The rail and conversation stores are in-memory projections; startup does not restore owned identity from webview localStorage (`core/src/session_store.rs:64-117,119-254`; `tauri-svelte-preview/src/routes/next/+page.svelte:1486-1510`; commit `65c2353`).
3. **Durable event persistence precedes display state.** A session row and event row commit atomically before sequence or live manager state advances (`core/src/session_store.rs:262-313`; `tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:2569-2733`; commit `a2236e2`).
4. **Generation and sequence reject stale asynchronous work.** Native requests, live events, snapshot rebuilds, capability reads, provider updates, source reads, and panel loads use generation, sequence, or monotonic ticket guards before applying results (`tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:2527-2566`; `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:508-530`; `tauri-svelte-preview/src/lib/shell/git/gitService.ts:202-220`; `tauri-svelte-preview/src/lib/shell/problems/problemsStore.svelte.ts:161-225`).
5. **Structured and terminal writers do not write concurrently.** Ownership and writer-lease states gate prompts, terminal sends, suspension, and handoff (`tauri-svelte-preview/src-tauri/src/agent_conversation/protocol.rs:346-380`; `tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:1021-1102,1898-2177`).
6. **Idle cost is bounded by lifecycle.** Agent adapters stop after quiescent turns, language servers start only in Full mode or while already warm, panels load only while visible, History and transcripts render bounded windows, resource polling runs only while open, and age or working clocks are scoped to visible rows (`tauri-svelte-preview/src-tauri/src/agent_conversation/manager.rs:3621-3632`; `tauri-svelte-preview/src-tauri/src/lsp.rs:68-128`; `tauri-svelte-preview/src/lib/shell/panelActivation.ts:206-297`; `tauri-svelte-preview/src/lib/shell/conversation/conversationTimeline.ts:187-243`; `tauri-svelte-preview/src/lib/shell/components/UtilityStrip.svelte:38-123`; commits `f12bf30`, `71d3d2c`).
