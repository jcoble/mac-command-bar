# Conversation surface

## What this portion is

This portion is the structured conversation view for an owned Codex, Claude, or Antigravity session. `ConversationSurface.svelte` chooses between the structured view and the raw terminal, derives the visible transcript, and connects the timeline and composer to the per-session store; `conversationService.ts` is the native command and event boundary that feeds that store (`tauri-svelte-preview/src/lib/shell/components/ConversationSurface.svelte:76-126`, `tauri-svelte-preview/src/lib/shell/components/ConversationSurface.svelte:372-455`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:458-500`).

## How it works today

### Event shapes and the two state layers

The native event envelope used by the conversation store is `AgentConversationEvent`, carrying `ownedId`, provider, adapter `generation`, monotonically checked `sequence`, timestamp, and a typed payload (`tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:541-548`). The canonical Agent Client Protocol (ACP) event envelope is `AgentEvent`, which adds an event type, provider instance id, optional native session, turn, item, and request ids, payload, provider metadata, and a redacted raw-frame reference (`tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:231-254`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:287-302`). The payload set includes connection, user and assistant messages/deltas, tools, children, approvals, plans, turns, commands, usage, terminal projections, errors, and rich ACP chunks such as thoughts, tool-call updates, diffs, permissions, and user-message chunks (`tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:416-468`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:470-539`).

`conversationReducer.ts` owns the small ordered session projection: `ownedId`, provider, generation, last sequence, desynchronization, connection state, suspension, timeline revision, native session id, active turn, usage, and a legacy `ConversationTimelineEntry[]` (`tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:19-34`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:644-658`). It rejects wrong owner/provider, old generations, and duplicate sequences; a gap advances the acknowledged checkpoint and returns without applying the payload so the service can resync (`tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:108-130`).

`conversationStore.svelte.ts` extends that reducer state into a reactive workspace keyed by stable `ownedId`. It adds the draft, per-session send error, view mode, sending flag, composer attachments, metadata, child agents and selected child, scroll positions, execution owner and writer lease, attachment maps, config and capability state, typed `AgentItem[]`, plans/tasks/commands, pending approvals and inputs, and a capped recent-event inspector (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:57-112`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:122-168`). Its module comment states that it performs no I/O and that the service feeds normalized events into it (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:1-6`). The two layers therefore carry the legacy ordered row projection and the richer reactive workspace/typed Agent Client Protocol projection separately; rich Agent Client Protocol kinds advance reducer ordering but are projected into typed items by the timeline/store (`tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:281-292`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:186-218`).

### Live streaming path

1. `startConversationEvents()` installs one Tauri listener for `agent-conversation-event`. Each payload is passed directly to `applyAgentConversationEvent`; a first user message can also title an untitled rail entry, a desynchronized session starts a resync, and `shouldClearConversationSending()` clears the sending flag only for terminal turn/error events (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:458-493`, `tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:9-17`).
2. `applyAgentConversationEvent()` rejects a provider mismatch before replacing a session, appends a short event summary to the recent-event tail, and calls `applyLegacyEventInPlace()` before typed projection (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:186-218`). The in-place path checks owner/provider, generation, and sequence; records a gap as desynchronized; and, for contiguous events, updates connection, user text, assistant deltas and completions, tools, approvals, plans, errors, turns, and usage in the indexed legacy timeline (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:240-251`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:253-395`).
3. The same live event is normalized by `agentItemFromEvent()`. A raw nested `payload.item` becomes an `AgentItem`; connection, turn, usage, and permission payloads do not become rows; plans, tools, diffs, command updates, errors, user/assistant messages, and reasoning chunks become typed items with stable ids and provider metadata (`tauri-svelte-preview/src/lib/shell/conversation/conversationTimeline.ts:732-830`). `mergeAgentItemInPlace()` updates the indexed item or appends it, and `applyTypedEventPayload()` updates capabilities, usage, plan/task arrays, children, pending requests, and reasoning completion (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:407-428`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:702-815`).
4. A `terminalProjection` event is not a legacy row in the first pass. The store unwraps its nested event type, provider instance, native session, item id, payload, and metadata into an `AgentEvent` and sends that to the same typed normalizer (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:193-216`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:382-392`). The store test names the contract: the common envelope sequence check accepts the first projection and rejects a repeated sequence before the nested projection can add another item (`tauri-svelte-preview/scripts/agentConversationStore.test.ts:575-621`).
5. Contiguous live typed events record presence history after projection; a gap suppresses that presence record until repair (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:216-218`). Presence maps turn start/completion and approval requests to working or needs-attention states, and `SessionPresenceIndicator.svelte` displays the result (`tauri-svelte-preview/src/lib/shell/conversation/sessionPresence.ts:144-183`, `tauri-svelte-preview/src/lib/shell/components/conversation/SessionPresenceIndicator.svelte:79-108`).

### History and resync path

1. `loadConversationForRead()` and `resyncConversation()` ask the native side for an `AgentConversationSnapshot` and then pass it to `applyAgentConversationSnapshot()`; the snapshot contains a connection, optional suspended flag, last sequence, and event array (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:434-456`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:669-674`). Commit `076abe7` describes this as history replayed from the database through the reducer (commit message body), while this front end reaches that history through `readAgentConversationSnapshotFromTauri()` (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:439-455`).
2. The snapshot path rejects an older generation and skips a same-generation snapshot when its newest sequence is not newer, the current session is not desynchronized, and connection facts have not changed (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:508-530`). Otherwise it runs `idempotentSnapshotEvents()`, which changes repeated completed replay records to usage placeholders and repeated replay deltas to empty deltas while preserving their sequence numbers (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:461-506`).
3. A new plain reducer state is seeded immediately before the first retained event of the bounded snapshot tail, then every event is applied with `applyConversationEvent()` (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:531-546`). The reducer's `terminalProjection` branch now calls `projectedTimelineEntry()`: it reads the nested `payload.item`, accepts only `user-message` and `assistant-message`, joins their content-block text, ignores blank items and non-message bookkeeping, and appends a completed legacy row (`tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:42-82`, `tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:248-258`).
4. After the legacy replay, the store builds a new workspace object off the reactive graph, preserves composer/workspace fields, keeps the connection generation, clears typed items and pending request maps for the rebuild, replays typed items and typed payload state a second time, retains only the recent event tail, and publishes the finished object once (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:547-617`). Snapshot replay does not call live presence recording; the store contract test explicitly checks that replayed completed turn events do not mutate presence history (`tauri-svelte-preview/scripts/agentConversationStore.test.ts:358-386`).

The paths therefore differ at the state boundary. Live events mutate indexed leaves of the existing reactive workspace, advance `timelineRevision` per changed display item, and record presence; history rebuilds a bounded event tail in a plain reducer/store object, suppresses replay duplicates, derives legacy projected messages and typed items in separate passes, and publishes once (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:407-428`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:551-617`). The current tests pin both outcomes: a repeated snapshot leaves one assistant item and two recent events, while a 2,000-event snapshot leaves 400 legacy rows, 400 typed items, and 200 recent events (`tauri-svelte-preview/scripts/agentConversationStore.test.ts:388-417`, `tauri-svelte-preview/scripts/agentConversationStore.test.ts:450-486`).

### From stored event to a row

`ConversationSurface.svelte` derives the root legacy timeline or the selected child's transcript, then calls `typedConversationTimeline()` with typed items, legacy entries, timestamps, previous display rows, and the sent-attachment map (`tauri-svelte-preview/src/lib/shell/components/ConversationSurface.svelte:84-117`). ## Why it is the way it is

- `cfc4c96` changed terminal transcript projection to use the journal-backed conversation event stream. The current store therefore treats the terminal projection as one ordered `AgentConversationEvent`, unwraps its nested canonical event for typed rendering, and lets the shared sequence check reject duplicates (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:193-218`, `tauri-svelte-preview/scripts/agentConversationStore.test.ts:575-621`).
- `076abe7` records that resumed history had been read and discarded because projected records returned the reducer unchanged. It also records that an imported generation-zero session has no capability handshake until its first use. The current reducer reads user/assistant message content from projected records, while connection/config logic preserves generation and starts generation zero on send (`tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:42-82`, `tauri-svelte-preview/src/lib/shell/conversation/conversationReducer.ts:248-258`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:567-603`).
- `cce129e` records two resume-seam decisions: duplicate replay is suppressed by stable item id rather than rendered text, and live updates mutate indexed leaves with a numeric `timelineRevision`. The current snapshot dedupe and live merge code implement those two paths, and the display projection reuses unchanged keyed rows (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:461-506`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:398-428`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTimeline.ts:638-649`).
- `7c629de` records that snapshot replay previously crossed the reactive graph once per event. The current snapshot builder assembles a plain object, builds its bounded recent tail, and assigns the finished workspace once (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:551-617`).
- `42c795d` records the transcript render-window boundary: newest 120 rows initially, one “Show earlier — N more” row, and another 120 rows per disclosure while preserving the viewport. The current constant, disclosure function, and component row implement that behavior (`tauri-svelte-preview/src/lib/shell/conversation/conversationTimeline.ts:187-243`, `tauri-svelte-preview/src/lib/shell/components/conversation/ConversationTimeline.svelte:234-247`, `tauri-svelte-preview/src/lib/shell/components/conversation/ConversationTimeline.svelte:394-403`).
- `69d42a1` records that Tauri's default drag/drop consumed files, that swallowed send failures made the composer appear to do nothing, and that an unread capability snapshot should not refuse an attachment. It also records the absence of provider image echoing, which is why sent attachments are claimed locally and carried across snapshot rebuilds (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:630-684`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:897-920`).
- `e3eca0e` records that attachment ownership had been only an in-memory message-id map. The current user-message payload carries optional `attachmentIds`, older records remain valid without it, and replay restores the image map asynchronously after text is visible (`tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:422-425`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:385-432`).
- `f84757f` records that snapshot rebuilding could regress the adapter generation and that a surface-level send error painted every session. The current rebuild keeps the connection generation, `sendTargetGeneration()` reads the current generation at dispatch, and `sendError` is a field on each workspace state (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:560-589`, `tauri-svelte-preview/src/lib/shell/conversation/conversationActivation.ts:74-91`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:68-75`).
- `b1efa75` records that two asynchronous gaps could route a message to another session. `sendStructuredMessage()` receives one `ownedId`, resolves the terminal from that owner, and uses that id through draft clearing, awaits, dispatch, and failure cleanup (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:542-558`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:657-684`).
- `9d9db16` records stale native answers racing newer events. The current store rejects older generations, same-generation stale snapshots, wrong providers, and capability results from a different generation (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:508-530`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:923-938`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:243-259`).

## What is stored, and where

- The live front-end workspace is `$state` under `conversationSessions[ownedId]`; each value contains the reducer session fields plus draft, sending, attachments, metadata, children, scroll, lease, config, capabilities, typed items, pending requests, and recent events (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:68-126`).
- The native conversation journal/snapshot is addressed through `read_agent_conversation_snapshot`'s wrapper and the `AgentConversationSnapshot` shape; this portion does not name a database table, but it receives the connection, suspension, last sequence, and stored event tail from the native side (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:434-455`, `tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:669-674`). The resume-history/database reason is recorded in `076abe7`.
- Draft text is stored per `ownedId` through `agent_conversation_set_session_draft`, `agent_conversation_get_session_draft`, and `agent_conversation_clear_session_draft`; the in-memory debounce, ordered write queue, and revision map are in `ConversationDraftPersistence` (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:64-94`, `tauri-svelte-preview/src/lib/shell/conversation/conversationDraftPersistence.ts:12-83`).
- Images are stored in the owner-scoped native attachment vault through save/read/delete commands and are represented in the front end by metadata plus a managed path; blob URLs are temporary preview URLs owned by the surface (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:151-168`, `tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:181-241`).
- The workspace capture used by the session rail stores mode, generation, owner, attachment ids, config, scroll positions, sequence/telemetry, writer lease, selected child, and last sequence; restore applies those values to the in-memory session (`tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:1192-1235`).
- Presence history is a Svelte store keyed by `ownedId`, with active turn and attention/acknowledgement timestamps; removing a conversation removes its presence entry (`tauri-svelte-preview/src/lib/shell/conversation/sessionPresence.ts:45-54`, `tauri-svelte-preview/src/lib/shell/conversation/sessionPresence.ts:222-234`, `tauri-svelte-preview/src/lib/shell/conversation/conversationStore.svelte.ts:1238-1241`).

## Known gaps

- `sessionRestart.ts` states that nothing currently calls `requestSessionRestart()`; its former caller was the rail Resume button, command-line sessions are switched off for now, and the registration is retained while that remains open (`tauri-svelte-preview/src/lib/shell/conversation/sessionRestart.ts:1-16`).
- Attachment listing is allowed to fail on older controller builds that do not have `read_agent_conversation_attachments`; the service returns an empty restored list while leaving draft and saved ids intact (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:190-215`). Replay hydration likewise returns with text still visible when a screenshot cannot be read (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:410-421`).
- Terminal transcript projection can fail before the agent accepts its first prompt; the service drops its registration signature on that failure so a later activation can register it again (`tauri-svelte-preview/src/lib/shell/conversation/conversationService.ts:299-317`).
- User-message journal records written before `attachmentIds` existed omit the field; the type keeps it optional, so those records replay without attachment ids (`tauri-svelte-preview/src/lib/shell/conversation/conversationTypes.ts:422-425`).
