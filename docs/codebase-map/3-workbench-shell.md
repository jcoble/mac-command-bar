# Workbench shell

## What this portion is

The workbench shell is the `/next` route and the shell modules it composes. The route owns terminal-session startup, session selection, persistence of session metadata, and the startup gates; the visual frame owns the outer Gridview, the center Dockview, the right-panel column, the bottom status bar, and overlay surfaces. Panel modules own their own data and loading, while the shell supplies the selected project and visibility decisions. (`tauri-svelte-preview/src/routes/next/+page.svelte:1-10`, `tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:1-7`, `tauri-svelte-preview/src/lib/shell/panelActivation.ts:8-53`)

## How it works today

### Startup sequence

1. The shell frame and tool column mount first; the route comment explicitly relies on both having handed over their controls before it applies the stored Problems location. (`tauri-svelte-preview/src/routes/next/+page.svelte:1441-1445`) The route then adds the `next-shell-document` class, applies the stored theme, installs window drag-and-drop suppression, subscribes to extension-probe events, starts conversation events, applies the stored Problems location, and registers stack handlers. The C# language-server disable call and conversation-event start are launched without awaiting them. (`tauri-svelte-preview/src/routes/next/+page.svelte:1419-1459`) These calls occur before the asynchronous block’s `try`, so this routine has no local `rail.error` assignment or specified shell error surface for a synchronous setup throw or a rejected fire-and-forget call. (`tauri-svelte-preview/src/routes/next/+page.svelte:1440-1461`) The shell frame creates the Gridview and center Dockview in its `onMount`; it lays out the parent frame before creating the center Dockview, and it reports a construction exception through `onError`. (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:93-163`)

2. The route creates the terminal backend and awaits the xterm module loader. If the route has been disposed at this point, it returns from startup. (`tauri-svelte-preview/src/routes/next/+page.svelte:1460-1464`) A failure from this awaited startup path is caught by the outer startup handler later in the routine and becomes `shell start-up failed: ...` in `rail.error`. (`tauri-svelte-preview/src/routes/next/+page.svelte:1535-1537`)

3. The route creates the terminal service with an exit callback that updates the rail and records the exit, then awaits service attachment. Disposal after attachment returns before the remaining startup work. (`tauri-svelte-preview/src/routes/next/+page.svelte:1466-1478`) Terminal-service or attach failures therefore go through the same outer startup error path. (`tauri-svelte-preview/src/routes/next/+page.svelte:1535-1537`)

4. If the extension-probe host exists, the route configures the probe runtime. It then lists live PTYs from the terminal backend. (`tauri-svelte-preview/src/routes/next/+page.svelte:1479-1497`) The route does not import a session list from webview localStorage: its comment states that the old import was removed because WebKit writes localStorage lazily and a deletion could be lost on quit. (`tauri-svelte-preview/src/routes/next/+page.svelte:1486-1497`; commit `65c2353`, whose message describes the deleted-list returning on the next launch.)

5. The route lists conversation sessions from Tauri, converts them to owned-session records, and reconciles those records with the database-backed rail. It records the live PTY sizes, treats reattachable records and exited records that still have a PTY as attachable, claims the pending-reattach map before any hosts mount, and hydrates the owned-session projection. (`tauri-svelte-preview/src/routes/next/+page.svelte:1498-1510`) A failure in this sequence reaches the outer startup error handler and sets `rail.error`; the message text is later passed to the shell overlay only while the Session center tab is active. (`tauri-svelte-preview/src/routes/next/+page.svelte:1535-1537`, `:1782-1783`)

6. Startup does not materialize a workspace map. A session selection later reads one normalized workspace row from SQLite, and the route retains only that active projection; removing a session deletes its workspace through the same native database boundary. (`tauri-svelte-preview/src/routes/next/+page.svelte:866-928`, `:1498-1517`; `tauri-svelte-preview/src/lib/tauriSource.ts:1494-1537`)

7. For every attachable session, the route waits for a matching terminal host and calls the reattach path. `hostFor` makes twelve attempts and returns `null` when no connected host appears; `reattachIfPending` then returns without adopting when the host or rail record is absent, so that missing-host path sets no error text. (`tauri-svelte-preview/src/routes/next/+page.svelte:721-752`) The pending guard is deleted before adoption; adoption uses the actual PTY size, and a failed adoption marks the session exited and persists that state. (`tauri-svelte-preview/src/routes/next/+page.svelte:746-761`) Reattach failures are collected rather than immediately shown, then `scanRail()` runs. (`tauri-svelte-preview/src/routes/next/+page.svelte:1518-1524`)

8. `scanRail()` clears `rail.error`, tries the native `list_agent_sessions` call, falls back to the bridge result when the native call returns no result or throws, and only exposes a native error when both native and bridge results are absent. Its outer failure path sets `rail.error` to `session scan failed: ...`. (`tauri-svelte-preview/src/routes/next/+page.svelte:680-706`) The route appends the collected reattach failures after the scan so that the scan does not erase them. (`tauri-svelte-preview/src/routes/next/+page.svelte:1520-1533`)

9. In the `finally` block, startup allows session panel loads. If a session was selected while the gate was closed, the route repeats `sessionPicked` and restores the active workspace after opening the gate. (`tauri-svelte-preview/src/routes/next/+page.svelte:1538-1549`) The `panelActivation` module separately holds center-panel announcements until one timer after the frame is ready, because Dockview emits them through microtasks. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:8-53`, `:206-245`)

10. A pagehide event snapshots the active workspace. On destroy, the route snapshots again, marks itself disposed, releases command, navigation, stack, session-library, probe, conversation-event, and source-intelligence handlers, disposes the terminal service, clears maps, clears theme appliers, and removes the route class. (`tauri-svelte-preview/src/routes/next/+page.svelte:1553-1584`)

### What the user sees when startup fails

- A Gridview or center-Dockview construction exception is kept in the page’s separate `layoutError` state. The page keeps it separate from `rail.error` because the shell mounts before the startup scan and the scan clears `rail.error`. (`tauri-svelte-preview/src/routes/next/+page.svelte:310-313`; commit `ef9de6a`, which records that putting the mount failure in `rail.error` made the message disappear.) `ShellFrame` keeps the shell hidden until it is ready and keeps teleported content in a `display:none` parking stage before that point. (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:167-208`) The page passes the layout message to `ShellOverlays`, whose fixed `role="alert"` strip is above the panes and has its own tinted background. (`tauri-svelte-preview/src/routes/next/+page.svelte:1764-1788`, `tauri-svelte-preview/src/lib/shell/components/ShellOverlays.svelte:141-160`)
- An awaited startup failure sets `rail.error` to `shell start-up failed: ...`; scan failures use `session scan failed: ...`, and session adoption/start/restart/close operations write their own text into the same rail error field. (`tauri-svelte-preview/src/routes/next/+page.svelte:680-706`, `:1001-1030`, `:1074-1138`, `:1174-1407`) The overlay expression includes `rail.error` only when `centerTab === 'session'`, so the message is not included while Editor or Diff is the active center surface. (`tauri-svelte-preview/src/routes/next/+page.svelte:1782-1783`)
- Settings is loaded dynamically. A failed import is stored as `loadFailure` and rendered as `Settings could not be opened: ...` in a role-alert inside the settings host. (`tauri-svelte-preview/src/lib/shell/components/SettingsHost.svelte:51-100`)
- A command selected in the palette is awaited; a thrown command is converted to `${row.label} did not finish: ...` and shown in a dismissible status message. (`tauri-svelte-preview/src/lib/shell/components/PalettePanel.svelte:76-84`, `:165-184`)
- A resource sample with an error is represented in the status-bar summary as the resource error text; no sample is represented as `Loading resources…`. (`tauri-svelte-preview/src/lib/shell/components/UtilityStrip.svelte:38-63`)
- The optional C# language-intelligence warm-up is not routed to the shell rail: `shellPanels.ts` records a failure as observational/editor status. (`tauri-svelte-preview/src/lib/shell/shellPanels.ts:36-59`)

### Panels, docking, and session workspaces

The outer frame is a horizontal Gridview with `sessions`, `center`, and `tools` regions, plus an optional `dock` below the center. The frame defines the default widths and limits, including sessions 220–560 pixels, tools 240–960 pixels, center minimum 420 pixels, dock minimum 180 pixels, and a folded sessions width of 52 pixels. (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:28-88`) The frame persists a serialized grid after a 250 ms debounce, ignores zero-sized layouts, and restores only when the stored panel IDs match the required current IDs; otherwise it builds the default grid. (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:355-395`, `:397-419`; `tauri-svelte-preview/src/lib/shell/layout/layoutStorage.ts:90-149`)

A panel is a named surface with a host element in the frame and a separate data activator. Gridview and Dockview own the host geometry; Svelte content is moved into the host and returned to a parking stage when the panel is disposed. (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:164-180`, `tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:76-160`) The panel activator receives the selected project and decides whether its service is allowed to read. (`tauri-svelte-preview/src/lib/shell/shellPanels.ts:67-141`, `tauri-svelte-preview/src/lib/shell/panelActivation.ts:151-297`)

The sessions fold flag is separate from the Gridview width. SQLite `app_settings` owns the global `shell.sessions-collapsed` value; the page keeps one live boolean, reasserts the region limits when opening, and repairs a restored width only when it is below the open minimum. (`tauri-svelte-preview/src/routes/next/+page.svelte:599-638`, `:1852-1874`) The serialized Gridview remains the separate geometry owner.

The center is one Dockview group containing three permanent panel IDs: `session`, `editor`, and `diff`. The native Dockview tabs are hidden in the Svelte frame; `CenterCornerTabs` selects the active ID. (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:162-208`, `tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:372-383`, `tauri-svelte-preview/src/lib/shell/components/CenterCornerTabs.svelte:44-116`) A removed roster panel is re-added on a later macrotask because Dockview emits removal before it disposes the panel host. (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:210-239`; commit `ef9de6a`.) Center persistence records the active panel and serialized layout, but restore activates only the saved `activePanelId`; it intentionally does not replay the serialized tree. (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:314-357`)

The layout contract treats one Dockview group as the stacked three-tab geometry: `dockGroupCount` returns one for the stacked roster and two for side-by-side leaves, and the exact-set test rejects the retired six-panel center roster. (`tauri-svelte-preview/scripts/layoutStorage.test.mjs:100-121`, `:220-251`)

`ShellFrame` lays out the parent Gridview before creating/restoring the center Dockview. The commit for this order records that restoring Diff while the parent was 0 by 0 corrupted the center geometry and Monaco diff bounds. (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:93-155`; commit `1c5aed6`.) The parking stage is `display:none`, so hidden terminal hosts do not measure as a 2-by-1 terminal grid. (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:185-208`; commit `ef9de6a`.)

The right column mounts eight panel bodies—Files, Source Control, Worktrees, Run, Context, Agents, Browser, and History—and changes only the `.showing` display class. (`tauri-svelte-preview/src/lib/shell/components/RightPanel.svelte:1-16`, `:54-82`) `panelActivation` still decides when the data services are allowed to load: Explorer loads for a selected project, source control/worktrees/stacks load only when visible, and a repeated selection of the same folder skips the reload. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:151-297`) The Problems dock is mounted at launch but does not load its data until Refresh; hiding it removes the Gridview dock rather than leaving an empty 180-pixel region. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:48-53`, `:248-283`; `tauri-svelte-preview/src/routes/next/+page.svelte:638-678`; `tauri-svelte-preview/src/lib/shell/components/DockPanel.svelte:1-55`)

The session rail is a Svelte projection with `owned`, `available`, `activeOwnedId`, `scanning`, and `error` fields. SQLite-backed session identity and metadata are hydrated into it by the page; the store itself does not perform I/O. (`tauri-svelte-preview/src/lib/shell/stores/sessionRailStore.svelte.ts:1-23`, `:25-69`; `tauri-svelte-preview/src/routes/next/+page.svelte:1498-1510`) Selecting a session checkpoints the previous workspace, stops and releases its frontend projections, points panel services at the new session, loads that session's SQLite workspace, and restores its center/right tabs. (`tauri-svelte-preview/src/routes/next/+page.svelte:925-1005`)

Each `SessionWorkspaceSnapshot` records editor open paths, drafts and view state, active and selected paths, scroll position, a project-qualified diff path, conversation state, browser restoration metadata, center state, and the right tab. Open paths are capped at twelve while retaining the active path and every draft. The page keeps only `activeWorkspaceSnapshot`; switching releases the departing editor state and reconstructs the arriving tab descriptors from its SQLite row. (`tauri-svelte-preview/src/lib/shell/sessionWorkspaces.ts:70-205`, `:416-441`; `tauri-svelte-preview/src/routes/next/+page.svelte:190-200`, `:917-925`, `:993-1005`)

### Navigation and activation

The navigation module exposes the center IDs `session | editor | diff` and right IDs `files | source-control | worktrees | run | context | agents | browser | history`. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:19-44`) A handler registration supplies `showCenterTab`, `showRightTab`, `openDiff`, `openUrl`, `focusComposer`, `sendToSession`, and `startSession`; registration merges fields, and clearing removes them. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:46-99`)

Callers use these operations as follows: opening a file publishes an `OpenFileRequest` on the file bus and then shows Editor; opening a diff awaits the diff handler and then shows Diff; opening a URL shows Browser before calling the URL handler; focusing or sending to a composer invokes the handoff and then shows Session; and starting a session returns the page-created owned ID or `null` when no handler is registered. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:101-159`) The navigation test pins those call orders and the no-op behavior before registration and after clearing. (`tauri-svelte-preview/scripts/workbenchNavigation.test.ts:26-49`, `:69-145`)

The page registers the handlers once during startup. `showCenterTab` and `showRightTab` update the page tab state, `openDiff` calls the Git service, `openUrl` calls the browser service, composer requests append to the selected draft and focus it, send requests append attachments and send, and start requests build a `ThreadStartRequest` before calling the page’s session-start routine. (`tauri-svelte-preview/src/routes/next/+page.svelte:316-365`, `:508-575`) Shell commands and row-jump actions use the same page-owned functions, so a palette command can bring a tab or session forward without importing another panel’s implementation. (`tauri-svelte-preview/src/routes/next/+page.svelte:455-575`, `tauri-svelte-preview/src/lib/shell/shellCommands.ts:44-201`)

### Themes and design tokens

The route imports the `/next` styles only in this route so the older shell’s global palette is not recolored. It also imports `themeChrome.css`, which supplies Dockview’s four chrome variables before theme application. (`tauri-svelte-preview/src/routes/next/+page.svelte:13-25`) `nextTokens.css` scopes the shared token names to `.next-shell` and `:root.next-shell-document`; the route owns the root class because overlay portals can be outside `.next-shell`. (`tauri-svelte-preview/src/lib/shell/styles/nextTokens.css:1-42`) `next.css` maps the shell tokens into shadcn variables and leaves the application’s old global baseline untouched. (`tauri-svelte-preview/src/lib/shell/styles/next.css:1-59`, `:124-242`)

`themeRegistry.ts` treats a theme as one record containing CSS palette tokens, Monaco colors/rules, and terminal colors. Houston is the default and Dracula is the second registered theme; every theme carries the same token names and editor/terminal slot sets. (`tauri-svelte-preview/src/lib/shell/themes/themeRegistry.ts:1-27`, `:96-150`, `:507-539`) The theme registry tests compare Houston’s token declarations with `nextTokens.css` and `themeChrome.css`, compare its Monaco object with the live editor appearance, and compare both registered terminal palettes with the terminal factory’s existing Dracula palette. (`tauri-svelte-preview/scripts/themeRegistry.test.mjs:57-170`, `:172-264`)

`themeService.ts` writes token properties to both `document.documentElement` and `.next-shell`, then invokes registered Monaco and terminal appliers. It resolves the saved ID through the registry, persists only when `persist` is true, and clears the token properties from both targets during route cleanup. (`tauri-svelte-preview/src/lib/shell/themes/themeService.ts:81-190`) The theme registry comments and commit `3e2817f` record that the two targets are needed because menus and dialogs are portaled outside the shell, and that the three palettes were combined after the old settings names did not change anything. (`tauri-svelte-preview/src/lib/shell/themes/themeRegistry.ts:1-27`; commit `3e2817f`.)

The settings dialog exposes the registered theme choices, app/editor/terminal fonts and sizes, terminal palette and external terminal application, Problems location, and the C# language-server switch. (`tauri-svelte-preview/src/lib/shell/components/SettingsDialog.svelte:65-234`) The C# switch calls the native setter; an unsupported result restores the previous setting and leaves an inline note. (`tauri-svelte-preview/src/lib/shell/components/SettingsDialog.svelte:298-324`)

## Why it is the way it is

- The route is an explicit startup orchestrator rather than a panel loader: its opening comment says terminal sessions are the only launch I/O, each panel owns its own state and loader, and the route reconciles stored sessions before hydrating the rail. (`tauri-svelte-preview/src/routes/next/+page.svelte:1-10`)
- Startup has separate Dockview and session gates. The panel-activation comments state that Dockview announcements arrive through microtasks and need one timer after the frame is ready, while session panel loads wait until startup reattachment is complete. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:8-53`) This keeps a remembered tab from loading its data merely because it was restored; a visible tab or selected session must pass through the gate. (`:206-297`)
- The session list is now database-authoritative. Commit `65c2353` says the previous webview-localStorage import caused deleted sessions to return because WebKit writes localStorage lazily, so the import and deletion path were removed; the page comment records the same change. (`tauri-svelte-preview/src/routes/next/+page.svelte:1486-1497`; commit `65c2353`.)
- The layout is sized parent-first. Commit `1c5aed6` records that restoring the center while its parent Gridview was 0 by 0 corrupted Diff and Monaco bounds, so `ShellFrame` lays out the parent before creating the center dock. (`tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:93-155`; commit `1c5aed6`.)
- Center tabs are permanent and parked content is not measurable. Commit `ef9de6a` records that closing a center tab stranded its live terminal and that a one-pixel parking box made xterm resize to 2 by 1; the current code re-adds removed roster panels and uses `display:none` parking. (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:210-239`, `tauri-svelte-preview/src/lib/shell/components/ShellFrame.svelte:185-208`; commit `ef9de6a`.)
- Fold state and width remain separate owners. Commit `5bfc336` records the historical localStorage race that established the need to reassert open limits; today SQLite owns the fold flag while the serialized grid owns width and drag limits, and the page still repairs only an undersized restored width. (`tauri-svelte-preview/src/routes/next/+page.svelte:599-638`, `:1852-1874`; commit `5bfc336`.)
- Panel data is visibility-driven. Commit `a47f897` records that panels had been built but mounted nowhere and establishes the rule that a panel reads nothing until it is visible; the current activation module encodes that rule and the Problems Refresh exception. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:8-53`, `:206-297`; commit `a47f897`.)
- Session tabs no longer stay resident across Assembly-session switches. The current route checkpoints one normalized snapshot to SQLite, releases the departing editor resources, and rebuilds the arriving lightweight descriptors; only the active workspace projection remains in Svelte. (`tauri-svelte-preview/src/routes/next/+page.svelte:747-814`, `:993-1005`; commit `6da033e`.)
- The Diff tab is shell-wide but follows the selected project. Commit `5691ace` records that a session switch could leave Diff showing the previous project; workspace state therefore stores both diff path and root, and `diffPathFor` clears the path when roots differ. (`tauri-svelte-preview/src/lib/shell/sessionWorkspaces.ts:354-387`, `:390-414`; commit `5691ace`.)
- The right column and bottom status bar are arranged as they are because the later shell changes moved machine/account readouts to a full-width status bar and moved settings into that bar. (`tauri-svelte-preview/src/lib/shell/components/UtilityStrip.svelte:1-18`; commits `bffc9d0` and `44a59a2`.)
- The center surface controls are floating pills rather than a top strip. Commit `1574198` records the removal of the top strip, the one-second post-switch hold, and the language control’s position/status behavior; `CenterCornerTabs` implements the timer and focus behavior. (`tauri-svelte-preview/src/lib/shell/components/CenterCornerTabs.svelte:50-116`; commit `1574198`.)
- Navigation is a registry seam because the module comment says panels do not import one another: the page registers handlers once, while unregistered calls are no-ops. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:1-15`, `:89-159`; `tauri-svelte-preview/scripts/workbenchNavigation.test.ts:26-49`.)
- Theme records include all three painted surfaces because commit `3e2817f` says the old CSS, editor, and terminal palettes lived in unrelated files and the settings selector did not repaint them. The theme service therefore paints both the document root and shell and calls registered editor and terminal appliers. (`tauri-svelte-preview/src/lib/shell/themes/themeService.ts:1-29`, `:81-190`; commit `3e2817f`.)
- Houston keeps the existing terminal colors. Commit `de71598` and the registry test say both themes carry the terminal factory’s long-standing Dracula palette, so choosing Houston does not repaint a terminal that already uses those colors. (`tauri-svelte-preview/src/lib/shell/themes/themeRegistry.ts:187-347`, `:349-505`; `tauri-svelte-preview/scripts/themeRegistry.test.mjs:230-264`; commit `de71598`.)
- The startup message has its own stacking position and background because commit `65c2353` records that the old message was behind pane stacking contexts and unreadable. `ShellOverlays` now places the message at a fixed high z-index with its own background. (`tauri-svelte-preview/src/lib/shell/components/ShellOverlays.svelte:141-160`; commit `65c2353`.)
- The `/next` CSS uses state classes rather than relational selectors. Commit `ccd3cc1` records that WebKit spent seconds invalidating `:has()` during bulk transcript insertion; the route class is toggled by route lifecycle and the scoped styles use the resulting state class. (`tauri-svelte-preview/src/lib/shell/styles/nextTokens.css:1-42`; commit `ccd3cc1`.)
- Settings uses `svelte-select` for its select control because the SettingsSelect comment records that Bits UI opened on pointerdown and dismissed on the same pointerup in the WebView. (`tauri-svelte-preview/src/lib/shell/components/SettingsSelect.svelte:1-7`.)

## Contracts other portions rely on

- Center surface IDs are exactly `session`, `editor`, and `diff`; right surface IDs are exactly `files`, `source-control`, `worktrees`, `run`, `context`, `agents`, `browser`, and `history`. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:19-44`; `tauri-svelte-preview/src/lib/shell/components/RightPanelTabs.svelte:27-38`)
- `ProjectSelection` carries an active root and a distinct `{ id, name, path }` project list; panel activators receive that shape and use `folderFor` to prefer a worktree `cwd` over the project path. (`tauri-svelte-preview/src/lib/shell/shellPanels.ts:67-105`, `tauri-svelte-preview/src/lib/shell/panelActivation.ts:56-80`)
- `registerWorkbenchNavigation` accepts partial handlers, and callers depend on the no-op behavior when no handler is registered. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:89-159`; `tauri-svelte-preview/scripts/workbenchNavigation.test.ts:26-49`)
- Navigation request shapes include `{ projectRoot, relativePath }` for diffs, `{ url }` for browser navigation, `{ ownedId, attachments?, appendText? }` for composer focus, `{ ownedId, text, attachments? }` for sends, and `{ prompt, cwd, projectPath, title, provider? }` for starts. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:46-87`)
- The file-opening contract is an `OpenFileRequest` on `openFileBus`; `openFileInEditor` publishes it before requesting the Editor surface. (`tauri-svelte-preview/src/lib/shell/workbenchNavigation.ts:101-111`; `tauri-svelte-preview/scripts/workbenchNavigation.test.ts:45-49`, `:92-99`)
- Panel activation contracts are `allowPanelLoads()`, `allowSessionLoads()`, `panelShown(id)`, and `sessionPicked(selection)`. The route calls these methods from the frame-ready, tab-selection, and session-selection paths. (`tauri-svelte-preview/src/lib/shell/panelActivation.ts:206-297`; `tauri-svelte-preview/src/routes/next/+page.svelte:1700-1755`)
- Layout consumers rely on the Gridview IDs `sessions`, `center`, `tools`, and optional `dock`, and on the exact-set roster checks before calling `fromJSON`. (`tauri-svelte-preview/src/lib/shell/layout/frame.ts:28-40`, `:355-419`; `tauri-svelte-preview/src/lib/shell/layout/layoutStorage.ts:66-149`)
- The center panel renderer contract returns a Svelte host element and a dispose function that returns the element to the parking stage; the center dock’s renderer map is keyed by the three center IDs. (`tauri-svelte-preview/src/lib/shell/layout/centerDock.ts:76-160`)
