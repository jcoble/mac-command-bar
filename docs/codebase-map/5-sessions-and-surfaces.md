# Sessions, history and side surfaces

## What this portion is

This portion records the sessions the app owns, the provider sessions it has scanned, the projection that joins those sources, and the left rail and History surfaces that display them. It also contains the lazy side surfaces attached to the selected session: source control, editor, files, browser, Problems, worktrees, context, run, resources, and usage. The rail and runtime stores remain the session authorities; the Session Library is a derived list and does not persist an archive or start a provider. [ownedSessions.ts:1-7](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:1), [sessionLibraryModel.ts:1-8](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:1), [sessionLibraryService.ts:1-7](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryService.ts:1)

## How it works today

### Session identity and the library record

An owned session is keyed by a CommandBar-minted `ownedId`. The code carries a provider's native session identifier for resume and transcript access, but the native identifier is not the primary key because a provider can mint a new identifier when a session is resumed. [ownedSessions.ts:1-7](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:1)

The owned record has two independent origins. `origin: 'app'` identifies an app-created ACP session, while `origin: 'external'` identifies a scanned session adopted into the app and retained as a PTY projection; `source: 'scanned' | 'fresh'` records whether the row came from a scan or a fresh creation. [ownedSessions.ts:48-63](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:48), [ownedSessions.ts:201-233](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:201), [ownedSessions.ts:235-270](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:235)

The `OwnedSession` fields are:

- `ownedId` is the durable row identity; `agent` is the normalized provider kind; `viaCmux` records a `cmux-` provider prefix; and `origin` and `source` describe runtime ownership and record origin. [ownedSessions.ts:48-55](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:48), [ownedSessions.ts:158-164](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:158)
- `title`, `model`, `projectPath`, `cwd`, `resumeCommand`, `nativeSessionId`, and `ptySessionId` describe what the session is called, where it runs, how it can be restarted, and which provider or PTY record it uses. [ownedSessions.ts:55-63](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:55)
- `state` is `live`, `background`, or `exited`; execution and runtime fields separately record structured or terminal ownership, provider instance, native session, turn, pending permission or input, capability revision, and the last runtime error. [ownedSessions.ts:15-46](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:15), [ownedSessions.ts:63-65](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:63)
- `completedAt` is written only by Mark done and Reopen; terminal exit does not write it, and a completed row can still have a running terminal. [ownedSessions.ts:66-76](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:66), [sessionCardModel.ts:42-67](../../tauri-svelte-preview/src/lib/shell/components/sessions/sessionCardModel.ts:42)
- `settledAt` is written only by Settle and Unsettle; it is not inferred from age, title, or process state. [ownedSessions.ts:77-84](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:77), [next/+page.svelte:404-423](../../tauri-svelte-preview/src/routes/next/+page.svelte:404)
- `branch`, `taskId`, and `pullRequest` are scanner metadata copied at adoption; `messageCount` and `latestTurnPreview` are copied from a bounded transcript scan; and `lastActivity` is the scanner's reading at adoption. [ownedSessions.ts:85-116](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:85), [ownedSessions.ts:224-232](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:224)
- `startedAtMs` is the stored start timestamp used for row age. [ownedSessions.ts:117-123](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:117), [WorktreeAgentRow.svelte:161-210](../../tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte:161)

Provider-scanned records are `AgentSession` values held in `rail.available`. They carry provider identity, native session id, project path, title or description, model, last activity, message count, resume commands, and a transcript `logPath`; they do not have an `ownedId`. [sessionRailStore.svelte.ts:11-23](../../tauri-svelte-preview/src/lib/shell/stores/sessionRailStore.svelte.ts:11), [sessionLibraryModel.ts:187-213](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:187)

Adoption normalizes `cmux-codex`-style providers, mints an `ownedId`, copies scanner metadata, sets the row to external, scanned, background, stopped, and closed, and leaves the PTY id empty until a terminal is started. [ownedSessions.ts:201-233](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:201)

The library converts an owned row to `key: owned:<ownedId>`, keeps the owned pointer, and projects the owned lifecycle to `working`, `done`, or `settled`. It converts a provider row to `key: provider:<provider>|<nativeSessionId>|<canonicalCwd>`, marks it `resumable`, and keeps the provider pointer. [sessionLibraryModel.ts:136-184](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:136), [sessionLibraryModel.ts:187-213](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:187)

Provider identity is the tuple `(provider, nativeSessionId, canonicalCwd)`. Titles are deliberately absent from that identity, and a null native id remains meaningful when its canonical working directory differs. [sessionLibraryModel.ts:100-134](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:100)

`buildSessionLibrary` projects owned rows first, drops duplicate owned ids, skips provider records without an id, and lets an owned row win when a provider record has the same compound identity. A provider scanner row can fill the owned record's missing transcript path when the identities match. [sessionLibraryModel.ts:216-263](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:216)

The library record fields are the merged key, source, owned and native ids, provider, canonical cwd, title, description, project, model, lifecycle state, runtime state, activity and update timestamps, bounded count, transcript path, optional prompt and turns, subagents, and the source pointers. `firstPrompt` is null, `latestTurns` contains at most one synthesized preview turn, and `subagents` is empty in the current bounded scanner projection. [sessionLibraryModel.ts:31-68](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:31), [sessionLibraryModel.ts:151-157](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:151)

`key` is either `owned:<ownedId>` or `provider:<encoded provider|native id|cwd>`; `source` says which projection supplied the row; `ownedId` and `owned` point to an app-owned record, while `available` points to the scanned provider record. `provider`, `nativeSessionId`, and `canonicalCwd` carry normalized provider identity; `title`, `description`, `projectPath`, and `model` carry display and project metadata; `state` is `working`, `done`, `settled`, or `resumable`; `runtimeState` carries the owned runtime state; `lastActivity` and `updatedAt` carry activity ordering; `messageCount` is the bounded count; `logPath` is the provider transcript path; and the remaining prompt, turn, subagent, and source-pointer fields carry the available bounded detail. [sessionLibraryModel.ts:31-68](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:31), [sessionLibraryModel.ts:159-213](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:159)

### Rail shelves and rows

The rail's shelf is determined by the user's stamps: no `completedAt` is Working, a `completedAt` without `settledAt` is Done, and a `settledAt` is Settled. The same rule drives My Work filters and library state. [myWorkViewOptions.ts:38-44](../../tauri-svelte-preview/src/lib/shell/components/myWorkViewOptions.ts:38), [sessionLibraryModel.ts:136-145](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:136)

The page writes those stamps through four actions: Mark done sets `completedAt`, Reopen clears it, Settle sets `settledAt`, and Unsettle clears it. [next/+page.svelte:404-423](../../tauri-svelte-preview/src/routes/next/+page.svelte:404)

The row's Done action moves it to Settled by setting `settledAt`; the Settled action clears both `settledAt` and `completedAt`, returning it to Working. [WorktreeAgentRow.svelte:581-611](../../tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte:581), [next/+page.svelte:404-423](../../tauri-svelte-preview/src/routes/next/+page.svelte:404)

`SessionRail` renders Working, Done, and Settled as sections of one scroll area. The view options select no grouping, status grouping, or project grouping; the same options select recent-activity or name sort and visible status filters. [SessionRail.svelte:1-9](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:1), [SessionsColumn.svelte:78-114](../../tauri-svelte-preview/src/lib/shell/components/SessionsColumn.svelte:78), [myWorkViewOptions.ts:8-30](../../tauri-svelte-preview/src/lib/shell/components/myWorkViewOptions.ts:8)

The row's presence is independent of the shelf. `live` and active runtime states read as working; approval or input pending sets the Needs you count; background is open but not selected; exited is stopped. The row draws a provider mark, title, project label, elapsed age, branch, Needs you or error text, and a finite working indicator only while it is on screen. Hover reveals only the quick-action controls already mounted in the row; it creates no delayed timer, portal, floating layer, or retained session snapshot. [WorktreeAgentRow.svelte](../../tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte), [SessionRail.svelte](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte)

Current project grouping uses each owned session's project path or cwd. Section expansion is a live `SessionRail` projection that resets with the component; it is not read from the former resume-group localStorage key. [myWorkViewOptions.ts:113-142](../../tauri-svelte-preview/src/lib/shell/components/myWorkViewOptions.ts:113), [SessionRail.svelte:44-84](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:44), [SessionRail.svelte:180-186](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:180)

The collapsed column uses the same working-then-done order. Done cells remain visible but dimmed, and each cell carries owned id, label, agent, cmux marker, state, done flag, and active flag. The global collapsed preference is `shell.sessions-collapsed` in SQLite `app_settings`; the page keeps only its live boolean. [sessionStrip.ts:14-86](../../tauri-svelte-preview/src/lib/shell/sessionStrip.ts:14), [next/+page.svelte:599-638](../../tauri-svelte-preview/src/routes/next/+page.svelte:599)

Row ordering can be dragged only inside one group. SQLite `app_settings` stores each group as an owned-id array under `rail.group-order.<groupKey>`; groups load when they first appear, a late restore cannot replace a newer drag, invalid saved entries are ignored, and current rows are appended. [SessionRail.svelte:51-121](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:51), [SessionRail.svelte:150-169](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:150)

Selecting a row invokes the registered page target first, then opens the center Session or Editor tab, or the Source Control sidebar. [sessionRowJump.ts:40-62](../../tauri-svelte-preview/src/lib/shell/components/sessionRowJump.ts:40), [sessionRowJump.ts:78-90](../../tauri-svelte-preview/src/lib/shell/components/sessionRowJump.ts:78)

### Explorer and Files

## Why it is the way it is

The explanatory comments and recent commit messages record these decisions:

- The CommandBar-minted `ownedId` is primary because provider identifiers can change on resume; provider ids are carried but never used as keys. [ownedSessions.ts:1-7](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:1)
- Done is a user answer, not a process observation. Commit `81175bd` introduced `completedAt`, kept rows after terminal close, and made removal a separate confirmed action.
- Settled is a separate explicit user shelf. Commit `8f4f127` added `settledAt` as an additive field, and the current code checks it before `completedAt`. Commit `8f4f127`, [sessionLibraryModel.ts:136-145](../../tauri-svelte-preview/src/lib/shell/sessionLibrary/sessionLibraryModel.ts:136)
- App-owned sessions use structured ACP while externally adopted sessions remain PTY projections. Commit `b91e29d` records that ownership split, and `ownedSessions.ts` preserves it during reload reconciliation. Commit `b91e29d`, [ownedSessions.ts:440-481](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:440)
- Message counts and previews reuse the bounded transcript text already read for titles. Commit `9bc3c27` records that no extra file read or wider read budget is used, so the count is a floor and excludes tool calls. Commit `9bc3c27`, [ownedSessions.ts:95-105](../../tauri-svelte-preview/src/lib/shell/ownedSessions.ts:95)
- The rail now reads SQLite as its authority. Commit `65c2353` records that the old empty-database localStorage migration was removed because WebKit's lazy localStorage writes made deletions return on the next launch and one migration failure could abort the shell. Commit `65c2353`, [next/+page.svelte:1486-1502](../../tauri-svelte-preview/src/routes/next/+page.svelte:1486)
- The rail is one scroll list with row-local hover actions and a bounded aging clock. Commit `a5d7ace` records the rail v3 change; the current component keeps one scroll container and `content-visibility: auto` rows. Commit `a5d7ace`, [SessionRail.svelte:252-263](../../tauri-svelte-preview/src/lib/shell/components/SessionRail.svelte:252), [WorktreeAgentRow.svelte:630-653](../../tauri-svelte-preview/src/lib/shell/components/WorktreeAgentRow.svelte:630)
- History is bounded because the startup scan once mounted about 4,000 rows in a hidden panel. Commit `71d3d2c` records the 25-row worktree window, Show more increments, visible-only mounting, and visible-only age clock. Commit `71d3d2c`, [sessionHistoryViewModel.ts:57-64](../../tauri-svelte-preview/src/lib/shell/history/sessionHistoryViewModel.ts:57), [HistoryPanel.svelte:255-262](../../tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:255)
- Resume was rebuilt as one action because the earlier three paths did not produce a sendable session. Commit `92e5ee5` records transcript import followed by ACP resume mode, with provider id, transcript, and folder required. Commit `92e5ee5`, [HistoryPanel.svelte:133-177](../../tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:133)
- Transcript opening was wired because provider transcript commands previously had no caller. Commit `7dba43c` records the normalized cmux provider, missing-field disabled reasons, title retention, and a backwards-growing wrapper with no current caller. Commit `7dba43c`, [sessionHistoryActions.ts:85-99](../../tauri-svelte-preview/src/lib/shell/panels/history/sessionHistoryActions.ts:85)
- Resume import writes whole conversation events and complete session rows because partial projections previously failed to decode and left no live listing entry. Commit `06147a5` records those failures and the current recovery path. Commit `06147a5`, [HistoryPanel.svelte:150-172](../../tauri-svelte-preview/src/lib/shell/panels/history/HistoryPanel.svelte:150)
- Explorer scans cancel an earlier native walk and do not cache results because the previous uncancelled walk ran in parallel and the old uncapped localStorage cache failed on large repositories. [explorerService.ts:13-24](../../tauri-svelte-preview/src/lib/shell/explorer/explorerService.ts:13)
- Problems use a whole-project route first and an open-file fallback so older desktop builds still show diagnostics without presenting an invented clean project. [problemsService.ts:14-27](../../tauri-svelte-preview/src/lib/shell/problems/problemsService.ts:14)
- Resource destructive actions share one explicit confirmation dialog because stopping a process and removing a folder are irreversible, and desktop webviews do not provide a reliable `window.confirm`. [ResourceConfirmDialog.svelte:1-14](../../tauri-svelte-preview/src/lib/shell/resources/ResourceConfirmDialog.svelte:1)
- Usage history uses backend-side aggregates because the store explicitly sends bounded summary, daily-total, and provider-total queries and does not move event or turn rows across IPC. [usageStore.svelte.ts:102-121](../../tauri-svelte-preview/src/lib/shell/usage/usageStore.svelte.ts:102)
