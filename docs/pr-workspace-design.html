Review flow

01 · Select

Open a PR

Choose Open, Mine, or Needs review. Project filters and search run in the GitHub query.

02 · Inspect

Read the evidence

See conversation, checks, changed files, and Assembly's diff presentation.

03 · Draft

Ask the helper

Only on click, Codex CLI or Claude CLI receives bounded PR context and proposes comments.

04 · Confirm

Edit and submit

Edit or remove comments, then confirm the exact repository, PR, target, and body.

Decisions in this proposal

AreaBehaviorReason
PlacementA center Dockview tab called Pull Requests. Keep existing Source Control PR creation, but open review in the center.Matches your VS Code example and gives files enough width.
DiffReuse Assembly's diff presentation for PR patches; keep hosted file selection separate from local working-tree state.It feels native without changing local Git selection.
Review commentsDraft an overall review and comments on selected changed lines. Each is editable; generation never posts.Your clarified request is review comments, rather than the opening PR description.
HelperPrefer an installed, authenticated CLI. Migrate legacy API-only settings to Codex CLI when installed, or Claude CLI when it is the installed option. API becomes an explicit Settings choice. Run draft calls without tools or write access.The intended default is CLI. The present helper backend still makes API requests, so it needs a transport change.
ModelUse the CLI's default model unless you select a model that CLI accepts. Show installed and signed-in status in Settings.An API model choice cannot be assumed to work through either CLI.
PostingConfirm each remote write, re-read repository and PR head, and reject a changed target. Never auto-retry an uncertain write.Public comments must attach to the version you reviewed.

Delivery sequence

Each milestone leaves a usable slice. The helper change also applies to existing title and inspect jobs.

1 · Read

Center tab and queue

Register Pull Requests in the center shell. Show Open, Mine, and Needs review across known projects with server-side filtering and pages. Refresh on activation or request, with clear authentication and rate-limit states.

Proof: a real PR opens from the full-size native tab, with no idle polling.

2 · Inspect

Detail, checks, and native diff

Show conversation, reviewers, checks, file tree, and side-by-side/unified patches. Reuse the presentation layer of the existing diff view. Let a selected changed line become an inline-comment target.

Proof: compare a real PR with GitHub and inspect both diff modes in the app.

3 · Helper

Make the helper CLI first

Route title, inspect, and review draft jobs through chosen Codex or Claude CLI. Keep API only behind an explicit choice. Migrate legacy settings without silently calling an API; show the chosen route in Settings.

Proof: each installed CLI works without an API key; explicit API mode remains deliberate.

4 · Draft

Prepare review comments

On click, send bounded PR context labelled as untrusted to the helper. Return editable overall and line-specific comments with visible file and line targets. No GitHub write occurs.

Proof: drafts can be edited, canceled, and regenerated without posting.

5 · Post

Confirm and submit

Preview the exact outgoing text and target, validate current repository and head SHA, then perform one confirmed GitHub write. Use the same confirmation for replies to existing review threads. Refresh after success; require inspection if the result is uncertain.

Proof: use a disposable PR for overall and inline comment submissions, a thread reply, cancellation, and stale-head refusal.

Acceptance gates

Native interactionCenter tab, navigation, conversation, checks, and diff work in Tauri at a verified 1710 × 990 viewport.
SafetyDrafts never post themselves. Each comment write has visible confirmation and revalidates repository, PR, target line, and head.
Helper behaviorInstalled Codex or Claude CLI is default. API requires explicit selection. Existing title and inspect jobs still work.
PerformanceNo idle PR polling, cheap offscreen lists, no perpetual animation, and app/WebView CPU near zero at rest.
VerificationRust and pure logic tests cover parsing, transport, and write guards. Visible UI gets native proof, not layout regression tests.
ScopeKeep existing PR creation. The PR tab now includes a confirmed merge action with merge commit, squash, and rebase choices. Close, rerun checks, and auto-merge remain in the larger TSK-808 work package for later.

End state: how we know it works

The goal is complete only when the implementation is running in the native Assembly app and these actions have been performed through computer use. A green build or mocked test does not substitute for this walkthrough.

Browse

At a verified 1710 × 990 viewport, open the full-size Pull Requests tab; use Open, Mine, Needs review, project filtering, search, and paging; open a real PR and inspect Conversation, Checks, and Files in both diff modes.

Helper

In Settings, confirm the migrated CLI choice and a working authenticated Codex or Claude CLI call without an API key. Exercise existing title and inspect jobs. Confirm that API transport is used only after explicitly choosing it.

Draft

Generate an overall review draft and an inline draft from a selected changed line; edit, cancel, and regenerate them. Verify that no GitHub comment appears before confirmation.

Post

On a disposable PR, confirm and publish an overall review, an inline comment, and a reply to an existing review thread. Check each result on GitHub. Cancel one confirmation and prove a changed PR head rejects a stale draft.

Merge

On a disposable PR, verify that a draft cannot merge, choose a merge method, cancel once, then confirm the exact repository and branches. Merge through the native PR tab and verify GitHub and Assembly both report the merged result.

Recover

Exercise missing or expired GitHub authentication, unavailable CLI, and a failed or uncertain write; verify actionable messages and no duplicate submission. Record idle app/WebView CPU and animation state while the PR tab is open.

Receipt

Record native screenshots or equivalent computer-use observations, exact commands and results for focused logic/backend tests, any unresolved limitation, and the final branch/commit state. Update the architecture page in the same commit as changed boundaries.
