TSK-1451: Installed font choices and live composer settings

Decision: list the fonts installed on the Mac in the existing Settings pickers. The interface picker receives every visible family, including monospace; app code, editor, and terminal receive only fixed-pitch families. Keep the app's shipped faces and system choices as dependable defaults, add no new font assets, and save the selected family through the existing SQLite settings row.

Boundary: one small native metadata command enumerates family names when Settings opens. It reads no font bytes, retains no font catalog, starts no watcher, and adds no import tool, schema, settings interface, resolver layer, or network request. TSK-1450 remains the authority for Ghostty rendering, PTY fit, and terminal lifecycle.

Confirmed current behavior

  • fontRegistry.ts:29-46 exposes only hard-coded shipped/system choices. SettingsDialog.svelte:101-117 builds all four font selectors from those lists or a separate seven-name terminal list. There is no installed-font command or CoreText use in source.
  • fontService.ts:28-50 already repaints --font-ui and --font-mono live and persists the selected string. CodeMirrorSourceEditor.svelte:203-211,457-460,1100-1103 already rebuilds its live theme from editor family and size. Those paths need family-name support, not replacement.
  • ConversationComposer.svelte:447-461,618 declares font: 14px/1.5 inherit. CSS-wide inherit cannot be mixed into that shorthand, so the declaration is invalid. settingsStore.svelte.ts:139-149 saves interface size, but the composer never reads it.
  • ghosttyFactory.ts:20-47 duplicates terminal defaults and can hand Canvas an invalid family string. The existing TSK-1450 live-settings path already refits the view and PTY after a real font change.

Minimal implementation

  1. Add list_installed_font_families to the existing application command module. On macOS, use CoreText's retained CTFontManagerCopyAvailableFontFamilyNames result, create only temporary family matches, confirm each match reports the requested family, and classify fixed-pitch families with CTFontGetSymbolicTraits(...).TraitMonoSpace. Return { families, monospacedFamilies } in Apple's UI order. RAII releases Core Foundation objects. The non-macOS build returns empty installed lists so the existing shipped choices remain buildable.
  2. Add the already locked objc2-core-text 0.3.2 and objc2-core-foundation 0.3.2 as direct macOS dependencies with only the required font, font-manager, trait, array, and string features. Register the command in the existing Tauri handler and add one typed tauriSource.ts wrapper; this is metadata only and has no background lifetime.
  3. Each time SettingsDialog opens, reuse its existing updateOwner.signal to await that wrapper. Merge and label the returned family names locally with the shipped presets, deduplicated by displayed family. Clear the installed lists when Settings closes, and ignore a result delivered after close or destroy. The interface list uses every visible family; the code, editor, and terminal lists use only fixed-pitch families. SettingsSelect gains one optional searchable prop, enabled only for the four font controls.
  4. Keep existing registry IDs for shipped interface and code choices. For an installed choice, use the exact family name as its saved string. The terminal picker always writes actual family names, including its shipped choices, because terminal.fontFamily is already a raw-family setting. Extend the existing getUiFont/getMonoFont functions to quote an unknown nonempty family name and append the existing CSS fallback. Do not reject a stored nonempty family during settings hydration: rendering saved Avenir, Meslo, or Google Sans Mono must not depend on a retained Settings component or a second native lookup.
  5. Make bundled JetBrains Mono the new-install terminal default, but preserve every existing saved terminal family, including Google Sans Mono. Remove the Ghostty factory's duplicate defaults; creation and live updates use settings.terminal and a valid "Chosen Family", monospace Canvas value. The existing live fit still updates backend PTY geometry.
  6. Import the reactive settings store in ConversationComposer.svelte. Bind settings.appearance.appFontSize to the textarea, replace the invalid shorthand with explicit font-family:var(--font-ui) and line-height:1.5, and make its existing resizePrompt() effect depend on both family and size so a saved multiline draft is remeasured immediately. No shell-wide type-scale change is included.

How another installed font appears

Install the font with Font Book, then reopen Settings. CoreText supplies its family name automatically; fixed-pitch metadata decides whether it appears in the code/editor/terminal pickers. No Assembly asset, registry row, license copy, restart, or import workflow is needed.
