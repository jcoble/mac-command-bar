TSK-1450: Replace xterm with Ghostty Web

Decision: patch ghostty-web@0.4.0 narrowly, replace the existing workspace-terminal renderer through its current factory seam, and remove xterm. The existing PTY backend remains the only backend.

Boundary: one session-owned utility PTY rooted at its workspace folder. Remove the bottom terminal and expose Ghostty as an addable right-pane tab alongside Worktrees. Do not restore terminal-based chat or retain a per-session renderer, add a fallback, add a second PTY path, or reinterpret protocol references that correctly describe xterm escape conventions.

Final owner choice: leaving the terminal fully disposes Ghostty but keeps its native PTY and shell running so variables, jobs, and command state resume. SQLite remains the authority for durable Assembly UI state; the live OS process is runtime state owned by Rust. No component, WASM object, or terminal display buffer is retained in WebKit.

Published-package patch

  • Replace the recursive idle requestAnimationFrame loop with a single-flight requestRender(). A frame is queued only by actual terminal activity and clears its handle after drawing.
  • Replace the renderer's perpetual cursor interval with a finite activity sequence when cursorBlink is enabled: show immediately, hide once at about 350 ms, show and settle by about 700 ms. Input, focus, and output restart that sequence. Blur and disposal clear both owned timers; blur leaves the cursor visible.
  • Add terminal visibility state used by the existing TerminalView.setVisible() contract. setVisible(false) cancels pending render and cursor work while writes continue updating WASM; setVisible(true) requests one catch-up frame. The application unmounts and disposes the right-panel terminal when it is left; it does not retain a hidden component.
  • Wire selection changes to requestRender(); retain the finite smooth-scroll and scrollbar-fade frames because each ends.
  • Allow theme changes after open() by calling CanvasRenderer.setTheme() and requesting a frame. This is app-correct because every shipped terminal theme currently uses the same palette; the patch does not guess or rewrite resolved WASM cell colours.
  • Add typed lineHeight support to terminal and renderer options and font metrics. Make fit remeasure loaded fonts before computing dimensions.
  • Store and remove the beforeinput handler and SelectionManager's document mousedown handler, cancel pending render/cursor work and FitAddon's resize-guard timer, and retain the existing wasmTerm.free() disposal. The document-listener leak was reproduced as 12 unmatched listeners, then fixed and re-proved at zero; immediate fit/dispose leaves no guard timer.

Release and reattach

  • Start the workspace PTY with the selected Assembly ownedId. Reopening first lists the existing Rust registry, reuses the one matching user PTY, and reads only the final four MiB of its bounded 16-MiB scrollback ring through the existing terminal APIs.
  • On leave, abort pending view work, unsubscribe output, disconnect resize observation, and dispose Ghostty. Do not call the PTY close command. The Rust registry, PTY, shell, and bounded scrollback are the only live survivors.
  • On return, create a new Ghostty view, replay the bounded tail, bind new output, fit, and focus. Reopening the Terminal right-panel tab is the exact action that handles an exited tombstone: replay its final bounded output into the new view, close the tombstone, and automatically start a fresh shell in that same view; do not add a restart control.
  • Make the existing Rust start_terminal_session path atomically return the live UserPty already registered for that ownedId, so overlapping mount/start operations cannot create a duplicate. Local Assembly-session deletion first closes matching UserPty entries only, then deletes the durable row; a kill failure leaves the row reachable for retry. Remote deletion does not touch the Mac registry. App shutdown closes the registry. Reuse the existing kill-and-remove implementation; do not add another command, terminal backend, or persistence table.
  • Reuse the existing TerminalOutputOrdering generation and sequence to make reattachment lossless. The terminal handle retains that ordering; the reader appends bytes and assigns their sequence while holding the same scrollback lock. The existing scrollback command changes in place to return { data, generation, sequence } from that lock, where sequence is the last sequence assigned to bytes in the snapshot and is -1 when no chunk has been assigned; it is never the next counter value. This adds no second API or fallback.
  • Preserve the existing stream envelope's generation and sequence through tauriSource.ts and terminalService.ts, cutting every current subscriber over in the same wave. The existing shared subscription gains an owned asynchronous readiness result for its current native-listener registration; it adds no second listener or generic stream engine. On mount, WorkspaceTerminal.svelte subscribes, queues early matching envelopes, and awaits that native-listener readiness before start or snapshot. Its abort cleanup removes the callback even while registration is pending, and the existing setup owner unregisters a native listener that finishes after the last subscriber left. It then writes the bounded snapshot and drops only envelopes from that same generation at or below the snapshot watermark; later sequences, every envelope after an empty -1 snapshot, and a fresh shell's new generation are delivered. This prevents a registration gap, replay gap, and duplicate output without a retained cache or generic replay abstraction.
  • Exact lifecycle files: components/WorkspaceTerminal.svelte reattaches and disposes only the view; components/RightPanel.svelte passes the selected Assembly ownedId; src-tauri/src/terminal.rs owns atomic same-owner UserPty reuse, ordered snapshot, close-by-owner, registry shutdown and focused tests; src-tauri/src/commands/terminal.rs returns the snapshot DTO; src/lib/tauriSource.ts, src/lib/shell/terminalService.ts, and src/lib/shell/stacks/runOutputService.ts preserve envelope metadata; scripts/nextTerminalService.test.ts and scripts/terminalViewLifecycle.test.ts cover the changed logic seams; src-tauri/src/agent_conversation/mod.rs closes matching user PTYs before successful local session deletion so a close failure leaves the durable row reachable; src-tauri/src/main.rs closes the registry on app exit. No UI structure tests.

Measured acceptance

  • The addable right-pane workspace terminal opens, accepts input, streams output, resizes/fits, selects/copies, scrolls, updates live font/theme settings, and disposes cleanly. The former bottom-dock terminal entry is absent.
  • Proof runs against an isolated copy of the owner's current database, leaving the owner's database unchanged. Open a terminal for each of ten real local Assembly sessions. Leaving each tab unsubscribes listeners/observers and frees Ghostty/WASM so frontend terminal diagnostics return to zero, while its Rust PTY and shell remain. Returning shows the same shell variables, jobs, working directory and running command after replaying at most four MiB from the existing bounded ring.
  • An exited PTY keeps its bounded final output until reopened or closed. Deleting an Assembly session removes only its owned PTY and shell; quitting the app removes the remainder. Rapid leave/return cannot create duplicate PTYs for one ownedId.
  • At rest after the finite cursor sequence, no Ghostty render RAF or cursor timer remains; cursor is visible within one second after activity. Idle app/WebContent CPU is sampled for about 10 seconds and remains near zero.
  • Native proof performs at least 12 terminal mount/unmount switches across the fixed ten sessions. A proof-only instrument around the public WASM terminal free() records one free per created terminal and is restored immediately; shipped product code contains no diagnostic hook.
  • /usr/bin/footprint captures complete process-group physical footprint with zero, two, and ten retained PTY/shell pairs, then after the warm switch cycle with the same fixed ten. Growth from zero to ten is expected because each live shell and its bounded history consumes memory; acceptance requires the ten-session footprint to plateau across repeated switching while frontend terminal diagnostics return to zero on every leave. Deletion reduces the retained count, and app quit returns it to zero.
  • Targeted TypeScript/static tests pass, including package-patch markers, factory cutover, scheduler ownership, theme registry, and rail/backend cutover. No structural, layout, colour, or styling regression test is added.

Expected patch size

The renderer cutover remains about 250–450 source and package-patch lines, excluding lockfile and documentation churn. PTY reattach, owner cleanup, and the ordered snapshot contract add about 120–180 source and focused-test lines across the named existing implementation and test files. If any part needs roughly twice its estimate, a native Ghostty build, a WASM palette rewrite, a compatibility adapter, a persistence table, or another subsystem, stop and return a revised proposal.
