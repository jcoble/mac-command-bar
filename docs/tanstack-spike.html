Top risks

  • One channel only: registering a second Tauri stream replaces the first (projection_streams.rs:99). The final prototype observes the existing frontend service after event application (conversationService.ts:94,1196).
  • Memory duplication: during migration, Assembly’s timeline and TanStack’s message graph coexist. Devtools add snapshot copies while active.
  • Unsafe gap repair: mid-stream setMessages() does not reset transient processor state. Treat a gap as a client reconstruction boundary.
  • Subscription retention: detach() is insufficient for a persistent subscribe adapter. Every destroyed session view must call dispose().
  • History semantics: TanStack’s built-in paging is count-based and grows the array; using it alone would violate Assembly’s byte cap.
  • Translation surface: Assembly has richer event kinds than the prototype. Approval and uploads should remain Assembly-owned instead of being forced through TanStack’s server conventions.

Persistence boundary: reconstructChat can page parent history when its store honors limit/before; full-array loading is a fallback, not inherent. Its save contract receives complete history, and child reconstruction loads a child without paging. Assembly should retain Rust SQL paging and provider-native resume.
