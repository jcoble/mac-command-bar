Remote workflow verification

TSK-1159 · Assembly Remote Dev · September 13, 2026. Native Mac app connected to the installed Linux workbox backend. These are observed functional results; timing limitations are listed separately.

How to use it

  1. Open Settings → Connections and click Connect beside Agent Workbox 2.
  2. Return to Sessions and select an existing remote conversation. No new chat or project selection is needed to reconnect.
  3. For new work, click New session, choose the workbox and browse its folder. Typing filters folder names; a slash enters the typed directory.
  4. The selected conversation supplies its Files, Git, model, effort and access settings. Use Disconnect in Connections to close the transport while retaining the saved machine.

Connecting uses the backend already installed under the remote user's home. It does not build or reinstall it, choose a project, or stop a running remote turn. Remove removes the saved connection; it does not uninstall the backend.

Performance observations and limits

Native Web Inspector reported document.getAnimations() = [] at rest. WebKit does not advertise the Long Task PerformanceObserver API, so no zero-long-task claim is made. Inspector and temporary diagnostic connections were closed. A ten-second sample of app PID 2680 and its responsibility-attributed WebContent PID 2685 recorded app CPU 0–0.2% and WebContent CPU 0–0.1%. RSS during that sample was affected by system memory reclamation, so it is not presented as a stable footprint benchmark.

Final native click-to-transcript DOM measurement: 192 ms, within the approximately 350 ms interaction target. The real app was switched from FINAL_START_OK to the bounded proof conversation; a one-shot MutationObserver measured arrival of its RECONNECT_OK transcript. Network RTT was 147–151 ms. Disabling TCP packet delay on both WebSocket endpoints and enabling SSH compression reduced the initial 58,830-byte snapshot from 453 ms to 148 ms; subsequent responses measured 147–156 ms. Folder and transcript projections load independently. This is a DOM readiness measurement, not a display-paint measurement: inspector docking delayed requestAnimationFrame callbacks, so those samples were excluded.

Remote Files deliberately has no idle filesystem watcher or polling loop. Open, expand and Refresh read current state; filesystem mutations refresh the affected folder. Remote language servers are not launched locally.
