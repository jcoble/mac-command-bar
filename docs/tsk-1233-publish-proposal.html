TSK-1233 — Publish a branch that has no upstream

One new item in the existing More source-control actions (…) menu, shown only while the current branch has no upstream. One remote: the item publishes straight to it. Several remotes: the item opens a submenu and the user picks one — nothing is guessed. Progress, success and failure reuse the panel's existing status/error line; retry is simply choosing the item again. No dialog, no new branch manager, no layout change. Accent bar on the left of an item marks what is new.

Behaviour rules

CaseWhat the menu shows
Branch has an upstreamNo publish item. Push/Pull as today.
No upstream, one remote“Publish to <remote>” — runs immediately.
No upstream, 2+ remotes“Publish to ›” submenu listing every remote; user picks.
No upstream, 0 remotes / read-only / busy / detached“Publish branch”, disabled, tooltip gives the reason.
Remotes not loaded yet (menu just opened)“Publish branch”, disabled, until the one listBranches() reply arrives.
Running / success / failureExisting actionStatus / actionError line under the commit row. Retry = choose it again.

Implementation shape (for review, not built)

File: SourceControlPanel.svelte only, roughly 40–60 lines, inside the existing DropdownMenu.Content after the remote-actions loop (SourceControlPanel.svelte:554-561).
Remotes: on the More menu's onOpenChange(true), when the branch has no upstream, call service.listBranches() once and keep remotes in local state. Event-driven, one call per open, nothing retained, no timer. listBranches already drops a reply whose root changed.
Run: service.publishBranch(folder, panel.status.branch, remote) — the branch and folder are captured at click time, so another session's branch can't be published by a late click (the service already rejects a mismatched root/branch).
Enablement: sourceControlPublishAction(panel.status, folder, context) for the disabled reason; the panel adds the “no remote” reason when remotes.length === 0.
