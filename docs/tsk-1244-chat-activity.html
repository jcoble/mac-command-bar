TSK-1244 — Live activity moves from the composer into the chat

Proposal only. The live label (“Thinking…”, “Writing…”, “Running a command…”) and its spinner move out of the composer's control row and into one status line directly under the newest part of the running reply. The composer keeps only the single Stop/Steer button, so its width and height no longer change while a turn runs.

2. The label comes from the newest item of the running turn

Newest item in the running turnLabelSource of truth
Approval request still openWaiting for approval…approval.state in requested / pending
Input requestWaiting for your input…kind: 'input'
Tool still pending or runningRunning a command… / Editing… / Searching… / Reading… / Using a tool…tool.state + tool.toolKind
Reasoning textThinking…kind: 'reasoning'
Assistant text not yet completedWriting…assistant.completed !== true
Anything else (turn just sent, a tool just finished, nothing new yet)Working…turn active, no more specific signal

No timer, no debounce, no new store: the label is derived from the transcript items that already arrive. Fast changes only swap the text inside a one-line row of fixed height; the spinner stays mounted for the whole turn, so it neither restarts nor flashes.

4. When the spinner runs

  • Mounted only while the session's turn is active (the same turnActive that shows the Stop button). Completion, cancel or failure unmounts it and its animations.
  • Pauses when scrolled off screen or when the conversation is hidden — the existing WorkingSpinner visibility observer already does this.
  • Session switch: the row follows the selected session's own state; switching to an idle session shows nothing. Sub-agent transcripts show no parent status line.
  • Reduced motion: the existing static ring.
