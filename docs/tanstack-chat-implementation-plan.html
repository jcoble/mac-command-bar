01 · Architecture decision

Adopt the Svelte client fully for content

Create one createChat instance for the selected transcript, one custom SubscribeConnectionAdapter connected to the existing native service, and one real UIProvider. Use TanStack’s UIMessage/UIPart traversal and component maps to render its canonical messages. There is no second frontend transcript or standalone StreamProcessor beside that client.

Rust + SQLiteComplete native items, durable sequence, execution and requests
Existing native serviceSelection, bounded page, snapshot/tail ordering, commands
Custom connection + createChatOne UIMessage graph, deltas, normal send bookkeeping
TanStack Svelte UIMessage/part dispatch into Assembly components

Use direct createChat and createChatUI at this dynamic connection boundary. A helper factory adds no useful behavior here. The documented custom connection accepts our Tauri channel or existing remote WebSocket; it does not require HTTP, a JavaScript server or TanStack provider adapters.

  • The per-tool-row fake chat host and provider in ConversationToolUI.

Sandbox support is useful for a separately scoped execution-platform decision; it is not a remote transcript transport replacement.

02 · Contracts to freeze before parallel edits

Translate content; preserve native commands

Snapshot and live stream

  1. Select by Assembly owned ID, native generation and a selection token. Subscribe before reading the snapshot, using the existing bounded race buffer.
  2. The native page returns complete native items, stable item IDs/order, older/newer cursors, truncation information and the sequence watermark from the same read boundary. It also returns or accompanies the native active-turn and pending-request metadata.
  3. The TypeScript mapper converts each complete native item once into a UIMessage. Publish a MESSAGES_SNAPSHOT, then only events strictly after its watermark, in native sequence order.
  4. The adapter is the only publisher into the client. Send acknowledgment never republishes stream chunks. Late results for a departed identity are ignored and the old observation is disposed.
  5. On reconnect, use the native reconnect path and authoritative selected snapshot. Do not additionally call automatic TanStack hydrate/joinRun or replay the entire turn into an already hydrated graph.

Keep native wire types independent of TanStack’s storage representation. The page can carry complete existing AgentItems plus metadata; a stateless boundary mapper produces UIMessage parts. Rust does not need to embed a JavaScript SDK or persist TanStack objects.

Normal send and message identity

chat.sendMessage owns the optimistic row and local submission/error state. Its adapter submits only the new prompt with existing attachments and provider context through the existing preparation/delivery command. Correlate its optimistic message ID with the native admitted user item ID, replacing the optimistic identity once; a native echo must never add a second user row. Do not infer that every user message in the client’s history is a new prompt.

Record the admitted native generation/turn before forwarding its terminal. Pre-admission or older-turn terminal events must not settle the new send. Admission failure rejects the send and preserves the existing draft-recovery behavior. Native turn identity remains authoritative; the client-generated run ID is correlation metadata, not a new native session.

The composer retains its existing capability-based busy behavior. Steering goes directly to the native current turn. It must not become TanStack’s abort-and-send queue mode. No second queue is introduced.

Native tool progress and full text correction

Use standard text/reasoning/tool-call chunks wherever their meaning matches. A running tool output update is not a tool result: TOOL_CALL_RESULT completes the call. Publish native running progress through CUSTOM and update only the matching canonical tool-call part through the public chat.setMessages callback. The actual terminal event creates the paired result and final status.

For complete window replacement or authoritative text correction, use MESSAGES_SNAPSHOT, not setMessages alone: the snapshot resets transient text segments. The pinned processor can preserve an older running-tool output during snapshot reconciliation. After publishing a snapshot, reapply each authoritative running call’s output and running state through the same CUSTOM path before releasing newer tail events; replace arguments and metadata when the snapshot supplies them. The focused fixture must show that prior complete/error state cannot override a native running call. This small adaptation updates the sole message graph; it must not build another journal or processor.

Do not feed native child transcripts into TanStack’s nested subagent processor. The reviewed version retains internal child state across some snapshots. Native child cards already have their own identity and controls; keep that metadata outside parent content. A selected child has its own bounded chat instance, disposed when it is deselected. Its transcript is read-only through that instance unless an existing native child-send capability explicitly supports it.

03 · History and performance

Bound complete message pages, not arbitrary delta fragments

The audit found no single 100 MB history request. Current snapshot/history calls request a 512 KiB soft payload budget. Larger total work can come from duplicate representations, repeated projection, oversized rows and reconnect replay over many pages. A page budget is not a total resident-memory bound.

Observed limitCurrent evidencePlan
Snapshot / history512 KiB requested; candidate limits 2,000 / 8,000 rowsKeep the initial soft budget; change selection to complete items and measure before changing the number.
Frontend raw journal20,000 events / 4 MiB; trims to 15,000 / 3 MiBDelete the resident raw-content journal after the complete-page cutover.
Snapshot race buffer20,000 events / 4 MiB; overflow resnapshotsRetain only this short-lived sequencing buffer, release on handoff. Do not turn it into a second transcript.
Selected child read4 MiB provider transcript tail; not full-history pagingKeep lazy selected-child loading and an explicit truncated-tail indicator. Do not eagerly load all children.
Remote replay1 MiB pages, repeated through missing eventsPreserve durable cursor correctness; measure cumulative bytes and sessions, not merely the page size.
Remote frame1 MiB request / 16 MiB response or event ceilingKeep actual transport ceilings visible in receipts; no claim that every oversized item fits.

Native SQL read

Use the existing events table and generated item_id. Add only the covering index demonstrated necessary by EXPLAIN QUERY PLAN for the agreed item query. Select candidate item boundaries, choose the latest authoritative payload, concatenate any required ordered deltas, calculate UTF-8 bytes and page/cursor existence in SQL. Return only the bounded selected items for typed conversion. Do not load an entire session and group or page it in Rust or JavaScript.

Delta-only historical replies need their complete prefix; a final row alone is not sufficient for every provider. The existing final-assistant SQL helper demonstrates ordered aggregation. The native page lane must prove an active item, a delta-only completed item and a full authoritative replacement using existing provider fixtures before client/store edits land.

No new projection table is approved by this plan. Start with the existing indexed journal. If its measured query cannot meet complete-item correctness and bounded work, stop that lane and return a small concrete schema proposal with migration cost and a revised diff budget. Do not silently introduce a projection framework or backfill service.

Retention and oversized content

Use true UTF-8 payload accounting (LENGTH(CAST(payload AS BLOB))), including the known SQL correction. Treat 512 KiB as the target for a selected complete-item window. Preserve the existing progress policy allowing one indivisible oversized item; report actual serialized bytes and truncation/oversize metadata. The existing 16 MiB transport error remains an explicit limit. This migration does not promise an arbitrary-size blob viewer or a hard process-memory cap.

In latest mode, append live content into the sole graph. When the existing retention high-water mark is reached, request one fresh complete window and replace it, releasing evicted items. Do not keep appending older pages indefinitely. While browsing an older window, process native activity and control metadata but do not admit out-of-window live content into that graph. Return to latest with an authoritative current page and watermark. No invisible JavaScript copy of the live tail is needed.

Memory acceptance — owner clarification, 1 October 2026

The migration must not add substantial sustained memory use. Compare the same long conversation on the same host before and after, measuring the complete native app and WebKit process tree rather than JavaScript heap alone. Record idle baseline, peak while streaming/paging and settled memory after repeated session/child switches and reconnects. Keep workload and measurement timing consistent; distinguish a temporary allocation peak from memory that remains retained.

Acceptance requires no material sustained increase outside the observed baseline variation and no continuing climb across repeated cycles. Release selected message graphs, listeners and child views on departure; verify that inactive sessions retain only lightweight metadata. If this gate fails, fix the retained ownership before rollout. No numeric memory improvement is claimed until measured, and no permanent memory-monitoring subsystem is added for this check.

Measure the suspected cost before adding rendering machinery

Record actual snapshot bytes, parse/materialization time, time to interactive transcript, live delta work, page replacement cost, retained messages and mounted rows on the same recorded long conversation before and after. Compare Mac and workbox separately. Use the existing session-interactive target (<350 ms) and verify idle activity returns to its baseline; report hardware, sample count and failures rather than claiming a universal speedup.

Owner update, 5 October 2026: TanStack Svelte Virtual is required. Use it with the bounded bidirectional data window. Virtualization mounts visible rows plus a small overscan buffer; it does not evict message arrays, tool output, subscriptions or native caches. Complete history stays in native storage and provider context stays with the provider. Keep one bounded selected message graph and release distant content as the data window moves; never retain all fetched pages behind a virtualized view.

Required chat scrolling and summary behavior

  • When reading older messages, incoming text, tools, new messages and completion must not drag the viewport to the bottom. Follow appended output and measured streaming growth only when the reader was already at the end. Jump to latest explicitly restores that behavior.
  • Use stable native item IDs and measured row heights. Preserve the visible item and its offset while prepending older history, appending newer history, evicting the opposite window edge, resizing streamed text/code, and expanding or collapsing work. Preserve disclosure and pending-input state when a row unmounts; do not keep every hidden component mounted to do so.
  • Render visible rows plus small overscan above/below. Keep network paging and data eviction outside the virtualizer. Use the official chat guide's end anchoring, conditional following and dynamic measurement where supported by the pinned Svelte package. Main currently declares version 3.13.35; verify its actual exports and source before using current-documentation APIs. If a compatible upgrade is necessary, pin it and update package.json/pnpm-lock.yaml in this lane. Delete replaced manual scroll compensation and follow logic; no competing scroll controller or runtime toggle.
  • A completed turn's “Worked for…” duration comes from full native turn bounds and stays constant while paging. It must not be recomputed from the loaded slice. Loading hidden work must allow progress to the preceding visible conversation, without repeated wheel movements merely changing the duration label.
  • Summary membership follows stable native turn/item identity and the actual final reply, independent of page boundaries. Intermediate assistant messages must not escape the fold because they happen to end a loaded slice. Show the actual final reply once. Preserve chronology and the ownership of user/steering messages; reproduce the owner's report of messages appearing after the wrong summary and correct misplaced membership rather than globally hiding all user messages.

Existing work: refresh against current main before implementation. TSK-1350's incremental older-page processing has already merged (PR 135); reuse it where relevant and do not reintroduce full-window replay. Coordinate with its full-turn duration/final-reply follow-up and TSK-1347/1369 grouping/anchor work, and TSK-1370 newer-page work. Check current status and reuse completed fixes rather than creating parallel implementations.

Steering and live streaming

Steering remains a required native capability. TanStack's busy queue and abort-and-send mode are not replacements for injection into the same native turn. Preserve Codex delivery timing. The inspected Claude adapter normally uses priority “now”; investigate and use supported delivery at an appropriate boundary without cancelling active work where available. Verify the installed runtime on each host. If that Claude runtime cannot provide the requested timing, record the exact limitation as unresolved acceptance; do not claim the TanStack UI fixes it or silently queue until the whole turn ends. Stop remains a separate explicit native action, and structured answers continue the original turn.

Render live deltas as they arrive; do not add a timer that simulates typing after receiving a completed chunk. Measure live delivery separately from history navigation. The earlier 17.65-to-6.5-second result measured traversal of one exceptionally long collapsed turn across many pages, including wheel movement and shorter stalls; it was not a single 17-second freeze or a live-streaming latency result.

Sources: TanStack Virtual chat guide, virtualizer and overscan, TanStack AI busy-message policies. Owner requirements above supersede the earlier optional-virtualization decision.

04 · UI and structured data

Use the actual component adapter without inventing missing APIs

Put one stable UIProvider above the selected transcript. Feed its real createChat host to the existing timeline, whose keyed rows render UIMessage/UIPart. Keep Assembly’s layouts, file actions and native controls through the adapter’s component maps. Reuse TanStack’s call/result matching and part traversal instead of writing another tool renderer dispatcher.

  • Every claim carries a file/line or command receipt. Every commit includes task URL, the appropriate architecture acknowledgment and ends “Committed-by: Codex” (or actual harness); never a co-author trailer.
  • Controller owns shared type/architecture edits. Remove each clean worktree on PR handoff and stop each owned browser/process tree immediately after use. Never discard dirty work.
