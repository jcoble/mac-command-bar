2. The big picture

There is one Rust program. Started normally it is the desktop app: a Tauri window with a Svelte web view inside. Started with --assembly-server on another machine it is the remote backend, with no window (tauri-svelte-preview/src-tauri/src/main.rs, in fn main). Each provider (Codex, Claude Code, Antigravity) runs as a separate ACP adapter process that Assembly starts and stops. The Android phone app is a separate Flutter program in mobile/.

One message, start to finish

  1. You press Send. The composer hands the text and attachments to the conversation service, which calls a Rust command.
  2. The Rust command gives the prompt to the runtime manager. If the session's adapter is not running, the manager starts it and resumes the provider's own session by its ID.
  3. The manager sends the prompt to the adapter over standard input and output. The adapter talks to the provider.
  4. Replies arrive as a stream of events (text, reasoning, tool calls, approvals). Normalization turns each one into a chat row, and the manager saves it to SQLite in order.
  5. Each saved row is pushed to the web view on the projection stream. The conversation store updates and the timeline draws it.
  6. For a session on a remote machine, steps 2 to 4 happen on that machine. The desktop sends the prompt over the WebSocket, and rows come back the same way and are saved on the desktop too.
  7. When the turn and all its follow-up work are quiet, the adapter process is stopped. The next Send starts it again.

The details of each step (IDs, suspend rules, how history comes back) are in main-architecture-explained.html.

4. Rules that keep it that way

Boundary rules

These come from the TSK-1512 refactor order (its "Boundary rules" section). That plan was not committed to the repository; it is linked from the TSK-1512 task. The plan is explicit that features are not fully independent: the composer uses provider settings, Git and the editor share markdown and diff renderers, and phone routes call desktop services on purpose. The rules name real public files instead of hiding dependencies behind new layers.

AreaRule
RemoteRemote cache, install and workspace code live under agent_conversation/remote/. Only remote/wire.rs defines the frames; only remote/server/ dispatches requests. Client and phone code import these, never copy them.
ConversationChat rendering and first send live under shell/conversation/. Outside it, only the listed public components may be imported (surface, composer, timeline, message parts, tool part, message, attachment lightbox, pending first message). No index file re-exports everything.
WorkflowsPanels import the workflow service, store, types and timeline only.
MessagesThe agent panel and the full Messages screen use the same shell/messages/AgentMessages.svelte.
HistoryProvider transcript readers exist only under agent_conversation/history/.
PhonePhone routes live only in agent_conversation/phone/ and write through the shared commands. No SQL in phone handlers.
Files, Git, Terminal, BrowserEach feature's internals stay in its folder; other code imports its public files. Generic components/ui stays shared. The older git helpers left in main.rs are a known exception.
ProvidersProvider install and update UI lives under shell/providers/. Provider-specific launch and sign-in behaviour stays in the Rust providers/ folder and the packaging scripts. Provider names in labels, transcripts, quotas, tests and contracts are fine.
SettingsSettings code uses the settings store and the theme and font services. No new direct storage writes outside the existing persistence bridge.
NormalizationRaw adapter content is parsed only in normalization/; the manager owns ordering, saving and lifecycle. No UI code imports raw ACP or adapter launcher code.
Files out of mainFile discovery, read and write code has one definition under files/; it does not go back into app startup.

What the hooks check on every commit

.githooks/pre-commit runs the async lifecycle scanner (scanSchedulers.ts) and then tauri-svelte-preview/scripts/commitChecks.ts on the staged files. .githooks/commit-msg checks the message and runs commitChecks.ts again for the fix-commit rule.

CheckWhat is stopped
File sizeA staged .rs, .ts or .svelte file over 600 lines. Files already larger are listed in tauri-svelte-preview/scripts/commitChecks.baseline.json (89 files) and may not grow; when one shrinks, its baseline must be lowered in the same commit.
Provider branchesA new if, match or case on "codex", "claude" or "antigravity" outside agent_conversation/providers/ and tests. 26 files have a recorded allowance that may not grow (the largest is manager.rs with 32).
Fix commits need a testA commit whose subject starts with "fix" that changes no test and has no No-test: <reason> line.
Removed locationsRecreating any of 15 old paths the refactor removed, such as remote_history.rs, phone_api.rs, git_pr.rs, orchestration.rs, shell/newSession/ or shell/components/conversation/. The error names the new folder.
Feature-internal importsImporting a feature's internal file from outside its folder: the 16 timeline row components inside shell/conversation/components/, the browser annotation canvas and bounds files, and terminal/ghosttyFactory. Two consumers are declared exceptions: Settings for ghosttyFactory and +page.svelte for browser panel bounds.
Message formatA Co-Authored-By line; a last line that is not Committed-by: <name>; on a tsk-NNNN branch, a missing Task: TSK-NNNN <Notion URL> line.
Architecture pageA commit that neither stages main-architecture-explained.html nor says Architecture: unchanged.

Where provider-specific code may live: freely in tauri-svelte-preview/src-tauri/src/agent_conversation/providers/, in tests, and in the adapter packaging and launcher scripts. Everywhere else it is held at its recorded count, and new cases are stopped. The TSK-1508 audit (section 5) went through the remaining cases and either made them apply to every provider or added a comment explaining why.

Known limits

  • The old codebase-map docs are out of date. docs/codebase-map/*.md (six files) were last changed on 2026-10-07, before the refactor. Many of their paths no longer exist. They were left as they are; use this page and the architecture page instead.
