Switching sessions destroys the editor; returning repaints it

2026-08-20. Owner's design: on leaving a session, save the editor's state and tear the surface down; on returning, repaint it from that session's saved state. Today the Monaco editor is one long-lived instance that is re-pointed (src/routes/next/+page.svelte:837 restoreWorkspace), so nothing is ever actually destroyed — which is also how global damage (the Monarch grammar poisoning) survived every switch. The in-memory retained-tabs cache must survive: it is what makes switching back cheap (src/lib/shell/sessionWorkspaces.ts:1-23).

The design, from recon with receipts: remount ONLY MonacoSourceEditor (the Monaco child), not EditorPanel. The child's own teardown already disposes everything it owns — editor instance, owned open-tab models, the external-target LRU, providers, observers, listeners (MonacoSourceEditor.svelte:2950-3029, disposal of owned models verified at :3018-3029). EditorPanel keeps its bus, status and language-bar subscriptions (EditorPanel.svelte:924-955), so no open-file request is parked. Dirty drafts live in the store (draftContent, editorStoreOps.ts:18-35), not in Monaco, so a remount cannot lose an unsaved edit. The one-shot VS Code services (csharpLanguageClient.ts:362-422) are global and are NOT re-initialised — the fresh child only awaits the already-resolved service promise.

2. What must NOT change

  • retainTabs / takeRetainedTabs and the whole retained-tabs mechanism (sessionWorkspaces.ts) — untouched. The page still snapshots on leave and replays on return (+page.svelte:793-812, 867-879); this spec only makes the surface those replays land on a FRESH one.
  • ensureApi / service bootstrap — untouched. If the fresh child triggers a second services start, that is a defect in the change, not something to shim around.
  • The old shell (src/routes/+page.svelte) — untouched.
  • No new store, no lifecycle manager, no abstraction. The whole feature is a prop, a {#key}, and a destroyed-guard.
