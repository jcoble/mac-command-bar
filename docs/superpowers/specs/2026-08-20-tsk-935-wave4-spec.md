## Design rule for all memory lanes (owner, 2026-08-20)
A hidden session owns no live state. Switching away from a session EMPTIES its panels' in-memory state — file tree, source control, editor — keeping only a small saved record (sessionWorkspaces-style); switching back REPAINTS from that record. The History panel renders only the top-level projects tree; everything beneath a project is lazy-loaded on expand and released on collapse/close. Memory must plateau: revisiting sessions or reopening panels costs ~0 beyond what is visible.

## Measurement rule (owner, 2026-08-20)
The in-app Resource Manager LEAKS 200-300MB per refresh (owner-measured, idle app, no sessions) and is disqualified as a measurement instrument until fixed. All memory lanes verify with external `ps -o rss=` sampling of the Web Content process, or devtools heap snapshots. New item 8c: Resource Manager refresh must replace its previous sample set (not accumulate), cap trend series to the visible window, and release on panel close.
