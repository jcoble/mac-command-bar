History panel rebuild

Fix why a project sometimes opens to nothing, then rebuild the card in the Worktrees tab's styling idiom. 2026-08-20.

Do the load path first

The panel intermittently renders an expanded project with zero sessions — the owner reports the same project, AssemblyTest2, showing everything on some opens and nothing on others. That is three bugs in the load path, not the card. Restyling on top of a loader that sometimes returns nothing would only produce better-looking empty states.

1. The three load-path bugs

Bug A — the key filter fails silently

sessionLibraryService.ts:120-128

async refresh(keys?: ReadonlySet<string>): Promise<SessionLibraryRecord[]> {
  const owned = source.getOwnedSessions?.() ?? [];
  const current = source.getAvailableSessions?.() ?? [];
  const provider = source.listProviderSessions ? await source.listProviderSessions() : [];
  const records = buildSessionLibrary(owned, [...current, ...provider]);
  const selected = keys ? records.filter((record) => keys.has(record.key)) : records;

refresh(keys) rebuilds the entire library from three sources, then keeps only the records whose keys were asked for. When the scan has not caught up — getAvailableSessions() stale, or listProviderSessions() still warming — selected is empty. Nothing throws. The project expands to a blank list and the reader is told nothing. Whether a project is full or empty depends on whether the scan finished before the click.

Bug B — one failure erases everything

HistoryPanel.svelte:168-171

const [, nextCheckouts] = await Promise.all([
  host.service.refresh(keys),
  listRepositoryCheckoutsFromTauri([project.path])
]);

Promise.all rejects if either side rejects. A git checkout lookup failing — busy repository, index lock, a worktree that moved — discards session records that loaded perfectly well. It lands in a catch at :177-179 that only writes console.error, leaving loadedRecords at the [] set on entry.

Bug C — the shared cache is wiped on every click

HistoryPanel.svelte:155 calls host.service.release() with no argument, which is held.clear() at sessionLibraryService.ts:130-133 — the whole store, across every project. An in-flight load belonging to the project just closed can clear the one being opened.

Why it is also slow

Every expand rebuilds the whole session library across all projects and providers, then throws away all but one project's keys — immediately after clearing the cache that would have made the second open free. The spinner added on 2026-08-20 reports the wait honestly; it does not shorten it.

Contract — the new pure module

The decision about what a load produced is pure arithmetic over three inputs, so it lives outside the component and is tested in plain Node, the same shape as sessionHistoryViewModel.ts and panels/files/fileTreeModel.ts.

/** What a project's load produced, and whether the reader can trust it. */
export type SessionHistoryLoadState = 'ready' | 'incomplete' | 'failed';

export interface SessionHistoryLoadOutcome {
  records: readonly SessionLibraryRecord[];
  checkouts: RepositoryCheckouts;
  state: SessionHistoryLoadState;
  /** Keys the view model listed that the scan could not produce. */
  missingKeys: readonly string[];
}

export function sessionHistoryLoadOutcome(input: {
  requestedKeys: ReadonlySet<string>;
  refreshed: PromiseSettledResult<readonly SessionLibraryRecord[]>;
  checkouts: PromiseSettledResult<RepositoryCheckouts | null>;
}): SessionHistoryLoadOutcome;

The rules, in full:

  • refreshed rejected → state: 'failed', no records. This is the only failed case; a checkout failure never is.
  • refreshed fulfilled and every requested key present → state: 'ready'.
  • refreshed fulfilled but some requested keys absent → state: 'incomplete', with the records that did arrive and missingKeys naming the rest. This is Bug A made visible instead of silent.
  • checkouts rejected → checkouts: {} and the state is unchanged. Sessions render without checkout decoration rather than not at all.

Changes in the panel

  1. Scope the release. :155 — host.service.release() becomes host.service.release(keys), moved below the point where keys is computed. Other projects' records survive.
  2. Settle, do not race. :168-171 — Promise.all becomes Promise.allSettled, and the two results go through sessionHistoryLoadOutcome.
  3. Serve from cache when it is already held. Before calling refresh, if every key in keys is already present in host.service.records, use those and skip the provider scan entirely. This is what makes reopening a project instant.
  4. Say what happened. Hold the outcome state in $state. On 'failed', render an error row with a retry that calls toggleProject again. On 'incomplete', render one quiet line under the loaded cards reading Still finding sessions — N not loaded yet with a retry that calls host.rescan?.() then reloads. Never leave an expanded project silently blank.

Not in scope

Do not change refresh's signature or behaviour in sessionLibraryService.ts — the sessions rail shares it. Do not add a caching layer, a request queue, or a retry policy. The cache already exists; use it.

Tests to write first

Create scripts/sessionHistoryLoad.test.ts. Four cases, all against the pure function, no DOM:

  1. a_failed_checkout_lookup_still_yields_the_sessions — checkouts rejected, refresh fulfilled with two records: state 'ready', both records present, checkouts an empty object.
  2. a_scan_that_is_behind_reports_what_is_missing — two keys requested, one record returned: state 'incomplete', missingKeys holds exactly the absent key.
  3. a_failed_refresh_is_the_only_failure — refresh rejected, checkouts fulfilled: state 'failed', no records.
  4. everything_present_is_ready — both fulfilled, all keys covered: state 'ready', missingKeys empty.

Register it in package.json as "test:session-history-load": "node --experimental-strip-types scripts/sessionHistoryLoad.test.ts", placed next to the other history entries.

3. Task two — the card, in the Worktrees idiom

Why cards differ today

SessionHistoryCard.svelte:153-256 is eight independent optional guards — messageLabel, subagentLabel, age, record.model, excerpt, record.firstPrompt, userTurns, record.subagents. Each is present or absent on its own, nothing reserves space, and nothing has a fallback. The cards are not variations on one design; they are every combination of eight switches.

Every control comes from the kit

src/lib/components/ui/DESIGN.md is the binding authority for this task — read it before touching a style. Nothing in this rebuild is hand-rolled markup with bespoke CSS. If a job has a component in the kit, that component is used; if it does not, the answer is a plain rounded-xl surface with kit primitives inside, not a new one-off.

Type and spacing — make it bigger than it is now

The owner's words are "things spaced and big enough font". The panel currently crowds 11 and 12px text into tight rows. The kit's scale, from DESIGN.md, is what fixes it:

  • --text-heading 16px at --text-heading-weight — the session name.
  • --text-body 14px — every label and every value. This is the body size and it is what the card should read at.
  • --text-quiet 13px — metadata beside a value, and the closing line. 13px is the floor for anything a person reads as content.
  • 11 and 12px are for small-caps group labels only. Nowhere else in this card.

Spacing follows the kit's own guidance rather than being chosen per element: 8px inside a control, 12px between rows, 16px between cards, 24 to 32px around the whole section. Written as --space-2, --space-3, --space-4, --space-5/--space-6. No raw pixel values.

The skeleton rule

SessionHistoryCard.svelte:153-256 is eight independent optional guards — messageLabel, subagentLabel, age, record.model, excerpt, record.firstPrompt, userTurns, record.subagents. Each is present or absent on its own, nothing reserves space, and nothing has a fallback. The cards are not variations on one design; they are every combination of eight switches. That is the whole of "a lot of them don't look like this".

The rule that replaces it: a card renders the same zones every time, and absent data reads as absent rather than as a different layout. Every label row is always present; an unknown value is an em dash in the muted colour. No zone is ever removed.

The card, zone by zone

  1. Collapsed row — chevron, session name at --text-heading, then chips for model and message count pushed to the right edge. The name truncates with an ellipsis; chips never wrap. Hover reveals HoverActions.
  2. Label and value rows, inline — a two-column grid so values align down the whole card, not a flex row per line. Label left in --text-quiet and the muted colour, value right in --text-body. The rows are fixed: Folder, Last activity, Model, Turns, Subagents. Paths truncate from the middle, everything else from the end.
  3. The turns accordion — a Collapsible, closed by default, in the place the Worktrees tab puts its > Why disclosure. See the rule below for what goes inside it.
  4. Section heading — a small-caps quiet label above the action cluster, the way the Worktrees tab writes What to do about it.
  5. Action cluster — Resume as the one default Button with a leading icon, then Open, Fork, Archive, Delete as ghost. An unavailable action is disabled and visibly dimmed, never hidden, and says why.
  6. Closing line — one quiet sentence at the bottom explaining the state, e.g. why an action is off or that no preview was stored.

What goes in the turns accordion

The owner's rule: the first turn, then the last two turns. That is the whole content — not the full transcript, and not a variable number that depends on what the scanner happened to capture.

  • Fewer than four turns available: show them all, in order, with no elision.
  • Four or more: first turn, then a quiet … N earlier turns line, then the final two.
  • No turns at all: the accordion still renders, and its content is the quiet line No turns were stored for this session. It does not vanish.

That last point also settles the owner's separate complaint that turns show sometimes and not others. The block is always there; only its contents change.

The CSS override pattern

Sizing a kit component happens through its data-slot, the way panels/worktrees/WorktreeRow.svelte does it — never by restyling the component itself:

.history-row :global([data-slot='list-row'] > button) {
  gap: var(--space-2);
  padding: var(--space-3) var(--space-4);
  font-size: var(--text-body);
}
.history-row :global([data-slot='hover-actions']) {
  right: var(--space-3);
}

Colours are never named. Use the shadcn slots — bg-card, text-muted-foreground, border-input, ring-ring — which styles/next.css already points at the shell's tokens. The two exceptions DESIGN.md allows are var(--color-text-2) and var(--color-text-3), for text tiers only.

Every interactive element owes the four things the kit requires: a hit target of at least 24px, a visible focus state (focus-visible:ring-ring/50 focus-visible:ring-3), a hover state, and a disabled state (disabled:opacity-50 disabled:pointer-events-none) that still explains itself.

Indentation

HistoryPanel.svelte:454 reads class={loadedProject.singleCheckout ? '' : 'history-nest'}, so single-checkout projects get no indent at all — the owner's "it's supposed to indent in some". Apply .history-nest unconditionally, and express its inset with tokens rather than the current margin-left: 0.875rem; padding-left: 0.375rem at :537-541: margin-left: var(--space-3); padding-left: var(--space-2), keeping the existing left border.

Scrollbar

The container at HistoryPanel.svelte:410 is <ScrollArea class="min-h-0 flex-1">. It renders a scrollbar component but the panel passes no scrollbarYClasses, so it never opts into visible styling and the reader is left on the mouse wheel. Pass a visible vertical scrollbar. Confirm the component's default in the running app before choosing the class — this is the one claim in this spec taken from the symptom rather than proven from the code.

Delete the duplicate spinner

HistoryPanel.svelte carries a hand-rolled .history-spinner with a @keyframes history-spin. components/conversation/WorkingSpinner.svelte now exists and does the same job. The repo's one-way-only rule means the hand-rolled one dies in this change; use WorkingSpinner. Its loop must stay tied to a real load and stop when the load ends — an animation at rest is a defect in this repo.

6. Rules that bind this change

Scope discipline

  • KISS — the smallest diff that makes the named tests and behaviours pass. Where two designs work, ship the one with fewer moving parts.
  • YAGNI — no code for hypothetical futures. "This will make it easier to add X later" is a reason to reject a change unless X is in this spec.
  • Unless named here, each of these is a defect: a new interface or base class, a new config option or flag, a compatibility shim or fallback path, a factory around one call site, a drive-by refactor of surrounding code, or a retry/caching/validation layer this spec did not ask for.
  • One problem per change. "While I was here" edits are rejected in review.

Project rules

  • Never write a CSS :has() selector, and never a Tailwind has-[...] variant. Put the state on the element that owns it.
  • No UI regression tests — nothing asserting on component structure, layout, panels, menus, colours or contrast. The four tests named here are logic tests over a pure function, which is what this repo still wants.
  • Animation must end. A loop is allowed only while real work is happening and must stop when it finishes or goes offscreen.
  • TypeScript only. No new .js or .mjs files. any is a last resort.
  • Browser testing is headless only, viewport 1710x990, verified with an innerWidth eval. Whoever opens a browser session shuts down its whole process tree and says so.
  • Never run git reset --hard. Read the diff of any file before restoring it.
  • Commit messages end Committed-by: <name>. No co-author trailer, ever.
  • This change alters no Tauri command, event, table or lifecycle rule, so its commit carries the line Architecture: unchanged.
  • If a required command fails, stop and report the exact error verbatim. Never substitute or invent a result.
