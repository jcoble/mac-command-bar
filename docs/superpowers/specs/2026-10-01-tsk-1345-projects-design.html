Technical design · TSK-1345 · 1 October 2026 · branch tsk-1345-projects · base ad11d88f2

Projects become the stable identity for sessions

Ship three complete cut-overs: first register projects and start new sessions from them; then group and backfill only by project_id; finally let existing sessions change checkout and safely remove disposable worktrees. The project never changes after session creation.

01. Outcome and fixed boundaries

Project

One normalized folder on one machine, held only by the desktop client's SQLite registry.

Session

Keeps one nullable project_id. Its cwd, worktree, and branch may change; its project may not.

Repository group

Combines project copies across machines by normalized remote URL. A project without a remote remains its own group.

Recommended split: keep the controller's PR1/PR2/PR3 split. It is complete at each boundary: PR1 replaces folder-root selection, PR2 replaces folder-derived grouping, and PR3 adds existing-session mutations without leaving two mechanisms for any one job.

02. Conflict that needs the owner's ruling

Conflict C1 — D6 versus D5/D7. A bare repository root is its Git directory, so git -C <root> rev-parse --is-inside-git-dir returns true. Rejecting every true result makes a bare repository project impossible, while D5 and D7 explicitly define one. The existing validator does not resolve this because it only compares the discovered Git root with the selected path (Verified tauri-svelte-preview/src-tauri/src/main.rs:1130-1187).

Smallest alternative: allow the selected root when --is-bare-repository is true and the selected path equals --absolute-git-dir; reject every other path for which --is-inside-git-dir is true. The rest of this design assumes that exception.

The explicit client opener is therefore a small enforceable boundary.

Path and repository normalization

  1. Expand ~ on the selected machine, canonicalize the existing directory, remove a trailing separator, and require an absolute result.
  2. Run git rev-parse --is-inside-git-dir, --is-bare-repository, and --absolute-git-dir. Apply C1's narrow exception; otherwise return “Choose the repository folder, not Git's internal data.”
  3. For a Git repository, read remote.upstream.url, falling back to remote.origin.url. Canonicalize common HTTPS, SSH URL, and SCP forms to lowercase-host/path-without-leading-slash-or-.git. Missing or unparsable remotes produce repo_key = ''.
  4. Default title is the canonical folder's last component; remove one terminal .git only for a bare repository.

  -> { cwd:string; worktree:string; branch:string };
  • Current checkout: list git worktree list --porcelain. For a ref already checked out, return that path without checkout. Otherwise run git -C <project-root> checkout <ref> and return root. A bare root with no checkout for the ref returns “Choose New worktree for this branch.”
  • New worktree: generate eight lowercase hex characters in the backend and run exactly git -C <root> worktree add -b assembly/<hex> ~/dev/work/worktrees/<repo>/assembly-<hex> <base>. Create parent directories only; do not create a project folder. Return Git stderr verbatim on failure.
  • Non-Git: allow Add project and Current checkout with cwd=root. Hide/disable ref and New worktree controls. Never initialize Git.
  • Errors: missing profile, disconnected remote, nonexistent/non-directory path, Git-data path, duplicate branch/path, dirty checkout, or Git launch failure remain in the draft. No stash, force, retry, or fallback.

05. PR2 — Project-only grouping, filtering, backfill, and adoption

Expected diff: 750–1,000 changed lines across 13–17 files, including tests and architecture.

Null project_id

→
Match on its machine
Exact root, deepest containing root, then equal Git common directory.

Write once

Backfill placement and remote handling

  1. At shell startup, hydrate the project registry first. Call backfill_session_projects before projecting local and cached remote sessions (Verified current parallel load is controllers/shellStartup.ts:38-49).
  2. The command matches local null rows in the desktop backend. For every connected remote profile, send only that profile's active project IDs and roots in RemoteCommand::BackfillSessionProjects; the remote backend matches and writes its own rows, then ListSessions refreshes the cache.
  3. Run the same remote backfill immediately after each later successful profile connection and before its first ListSessions. Offline rows remain null and appear under No project until that machine connects. Re-running is safe because SQL updates only WHERE project_id IS NULL.
  4. At adoption, map the scanner's folder before begin_import; pass that optional ID through import and ensure. This is the same matcher command, not a TypeScript path heuristic.

Mutation contracts

  mayRemoveWorktree:boolean, path:string|null, projectRoot:string|null,

}
delete_session(ownedId, removeWorktree:boolean, force:boolean) -> void
  1. Resolve the immutable project and its machine. If the selected ref is checked out elsewhere, update the session to that worktree; otherwise run checkout in the project root. On Git failure, show stderr in place and change no session fields.
  2. New worktree uses PR1's exact D8 operation, then updates only cwd/worktree/branch through the existing checkout command. It never changes projectId.
  3. Deletion preview offers worktree removal only when the path is not the normalized project root, is a registered Git worktree, and no other non-deleted session on that machine has that normalized path.
  4. On confirm, the backend rechecks sharing. Try git worktree remove <path> without force before deleting the session. If Git reports changes, return the exact short-status lines for a second prompt. Only force=true after that prompt runs git worktree remove --force. Declining the second prompt may delete the session while leaving the worktree.
  5. Archive changes session state only and never previews, checks, or removes a worktree.
