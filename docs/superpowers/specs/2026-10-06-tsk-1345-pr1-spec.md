## 2. Data contract (lands in 1a)

### 2.1 SQLite, `sessions.db` schema 19 → 20

Same schema on the desktop and on remote hosts (remote hosts never write `projects`; they only store `sessions.project_id`).

```sql
CREATE TABLE IF NOT EXISTS projects (
  id          TEXT PRIMARY KEY,      -- UUID v4 from the Tauri crate (uuid is already a dependency, S/../Cargo.toml:53 [V])
  machine     TEXT NOT NULL,         -- 'local' or a saved remote profile id
  root_path   TEXT NOT NULL,         -- canonical absolute path on that machine, no trailing slash
  title       TEXT NOT NULL,
  repo_key    TEXT NOT NULL,         -- normalised remote URL, '' when none
  created_at  INTEGER NOT NULL,      -- unix ms
  UNIQUE (machine, root_path)
);
-- sessions: new nullable column, added only if missing (pragma_table_info check)
ALTER TABLE sessions ADD COLUMN project_id TEXT;
CREATE INDEX IF NOT EXISTS sessions_project_idx ON sessions(project_id);
```

Rules:
- **Write-once.** `upsert_session_on` sets `project_id = COALESCE(sessions.project_id, excluded.project_id)`. No other statement updates `project_id` in PR 1.
- **Back-fill.** None in PR 1. Every existing row keeps `project_id = NULL`. PR 2 back-fills (rule in the design doc, section 5) in the same PR that switches grouping to projects, so grouping never reads a half-filled column.
- **Saved roots (one-time import, 1a).** At desktop startup, if the app setting `new-session.custom-project-roots` exists, `import_saved_project_roots` reads it (`value_json` is a plain JSON array of `{ id, name, path }`: `persistCustomRoots` at `projectRootsStore.svelte.ts:122-128` [V] passes the array to `writeAssemblySettingFromTauri`, which stores `JSON.stringify(value)`, `tauriSource.ts:2406-2409` [V]; skip anything that is not an array or an entry without a string `path`). For each entry whose `path` starts with `/`: `inspect_project_folder_sync(path)`, then `insert_or_get_project` with `machine = 'local'`. Entries that fail inspection are skipped and logged (`path` and reason) to the backend log. Then delete both `new-session.custom-project-roots` and `new-session.last-project-root`. Once the key is gone the import is a no-op; nothing else ever reads either key. The two hard-coded paths in `F/sourceData.ts:539-550` [V] are not imported.
- **Duplicates.** Adding the same (machine, root_path) returns the existing row.
- **Machine removed.** Projects whose `machine` is neither `local` nor a saved profile id are not listed in the menu (filtered in TS). Rows are not deleted.

### 2.2 Folder inspection (runs on the machine that owns the folder)

`inspect_project_folder_sync(path: &str) -> Result<ProjectFolderInspection, String>`:
1. Expand a leading `~` / `~/` to `$HOME`. Canonicalize. Not found → `Err("That folder does not exist.")`. Not a directory → `Err("That path is a file. Choose a folder.")`.
2. `git -C <path> rev-parse --is-inside-git-dir` prints `true` → `Err("This is git's internal folder. Choose the repository folder instead.")` (exact mockup 3b copy; this also refuses a bare repository root such as `~/dev/work/mac-command-bar` on the workbox).
3. `git -C <path> rev-parse --show-toplevel` succeeds and differs from the canonical path → `Err(format!("This folder is inside the repository at {top}. Choose that folder instead."))`.
4. Git repository: `repo_key = normalize_repo_key(url)` where `url` = `git config --get remote.upstream.url`, else `remote.origin.url`, else `''`. `title` = last segment of `repo_key` when non-empty, else the folder name. `is_git = true`.
5. Not a repository (rev-parse fails): `repo_key = ''`, `title` = folder name, `is_git = false`. **Never run `git init`.**

`normalize_repo_key(url)`: accept `https://[user@]host[:port]/a/b(.git)`, `ssh://[user@]host[:port]/a/b(.git)`, `user@host:a/b(.git)`. Output `lowercase(host) + "/" + path` with no leading `/`, no trailing `/` or `.git`. Anything else (file paths, empty) → `''`.
