Session rail redesign

Every row states three things and stops: what the session is, where it lives, and whether it wants you. Everything else — actions, machine, full paths, cost — appears on hover and takes no width when it is not needed. Rendered in the shell's own palette (nextTokens.css), at 300px rail width.

1 · The rail

Two-line rows, three groups, nothing always-on

Presence is a dot, never a word. A stopped session shows a hollow ring and says "Stopped" only in its tooltip, so the title keeps the full width. Clicking a row loads and readies the conversation, so there is no Start button — and no close-terminal button when no terminal is open.

What the rail does today: a "Stopped" label eating a third of the width, "No project recorded" on every row, a permanent strip of near-invisible dot-sized icons, and titles cut off under it.

What changed

  • Presence is a dot. Working pulses in the mint accent, needs-attention is amber, idle is a solid grey, stopped is a hollow ring. The word "Stopped" lives in the tooltip only.
  • No always-on controls. The four action icons appear only on hover or keyboard focus, in a rounded cluster flush to the right edge, with a gradient that fades the title underneath instead of clipping it.
  • 16px glyphs with real surfaces. Each button is 26x26 with its own hover fill and a colored accent — mint for Session, blue for Editor, green for Git.
  • No Start button. Clicking a row loads and readies the conversation; a stopped session resumes on the first send. No close-terminal button unless a terminal is actually open — it moves into the Details menu.
  • Meta line reads left to right: project, branch, model chip, then last activity right-aligned.

2 · Hover detail card

Everything the row could not say, to the right of the row

The card is placed in window coordinates beside the hovered row, never below it, so it never covers the neighbouring rows you are comparing against. Icon plus 13px text, one fact per line. It falls to the left side of the rail when the window has no room on the right.

Lines the app does not know are simply left out — the card shrinks rather than printing a placeholder sentence.

Rules

  • Appears after a short delay on hover, immediately on keyboard focus, and is not interactive — the pointer passes through it.
  • 336px wide, 13px body text, 15px icons at --color-text-3 so the values read as the content and the icons as the label.
  • Values that would wrap (paths, branch names) truncate with an ellipsis; the full text is available in the Details panel.
  • Cost and token lines appear only when the provider reports them.

3 · New session, in the thread

The separate form goes away

Pressing + opens a fresh thread pane instead of a dialog. You type the work first; the settings sit under the composer as pills and stay editable until you send. The session is created on the first send, with whatever the pills say at that moment.

The model pill is shown open: providers are grouped headings, the current pick carries a tick, and the right-hand hint says what each one is for. Effort, access, project and branch open the same way.

Behaviour

  • Nothing is created on open. The pane is a draft — no worktree, no process, no rail row — until you send.
  • Pills stay editable until then and each remembers the last value you used for that project.
  • The branch pill carries the "new worktree" toggle, so choosing where the work happens is one control rather than two.
  • On send the draft becomes a real session, the pane keeps its scroll position and content, and a row slides into Working.
  • The title on the rail row is generated from the first message, so rows read like the work rather than like a branch name.
