### S1. Pure tab model and snapshot shape (test first) — lands in one commit with S2
**Create `src/lib/shell/layout/topTabsOps.ts`** (pure, about 140 lines):
```ts
export type TopTabKind = 'editor' | 'browser' | 'diff' | 'git-history' | 'pull-requests';
export type SingletonTabKind = 'diff' | 'git-history' | 'pull-requests';
/** 'editor:<absolute path>' | 'browser:<tab id>' | 'diff' | 'git-history' | 'pull-requests' */
export type TopTabKey = string;
export interface TopTabRef { kind: TopTabKind; id: string }          // id = path | tab id | kind
export interface LiveTabSources { editorPaths: readonly string[]; browserTabIds: readonly string[] }
export interface SessionTopTabsWorkspace { order: TopTabKey[]; activeKey: TopTabKey | null }

export function topTabKey(ref: TopTabRef): TopTabKey;
export function parseTopTabKey(key: string): TopTabRef | null;     // splits on the FIRST ':' only
/** Stored order filtered to tabs that still exist (singleton keys are kept), then new live
 *  editor keys in openFiles order, then new browser keys in tab order. */
export function topTabRow(order: readonly TopTabKey[], live: LiveTabSources): TopTabKey[];
export function resolveActiveKey(row: readonly TopTabKey[], chosen: TopTabKey | null): TopTabKey | null; // chosen if in row, else row.at(-1) ?? null
export function openTopTab(row: readonly TopTabKey[], key: TopTabKey): TopTabKey[];   // append once
export function closeTopTab(row: readonly TopTabKey[], active: TopTabKey | null, key: TopTabKey)
  : { order: TopTabKey[]; activeKey: TopTabKey | null };          // right neighbour, else left, else null
export function normalizeTopTabs(value: unknown, live: LiveTabSources): SessionTopTabsWorkspace | undefined;
```
Every change writes `order` back from the current `row`, so dead keys never pile up.

  chosen = $state<TopTabKey | null>(null);

## 3. Native-browser overlap rules
1. **Placement** only when `BrowserPanel.visible` (pane showing, active kind `browser`, `toolsRailWidth > 0` — reported by `onToolsWidthChange` after Gridview layout, `ShellFrame.svelte:114-119`). Without this gate a browser tab chosen while the pane was absent would create its view at the old `floatingBounds` (`browserModel.ts:390-397`) for one frame (`frame.ts:481`).
2. **Where:** `hostRect` (`BrowserPanel.svelte:230-243`) and `hostRectFitsPanel` (`browserPanelBounds.ts:77-90`) unchanged; the pane is the tools region, and when expanded the center sits at 0 width at the sessions edge.
3. **Leaving the browser tab** releases every native view (`BrowserPanel.svelte:757-766`); tab ids survive through the reactive `restored` list.
4. **Covering:** anything floating over the pane takes a `coverBrowser()` token while open: the drawer, a tab hover card, the browser ⋯ menu, an editor-tab context menu, EditorPanel's close-unsaved dialog.
5. **While covered** (`count > 0`, visible, active tab, no annotation still): keep the live view, call `captureNow()` (`:411-418`); when the capture arrives and still covered, show the image in `.page`, set `coverReady`, `onScreen` false → placement `HIDDEN` (`:723-734`). When count returns to 0: revoke the image URL, `coverReady = false`, `layoutTick++`. If capture fails, hide anyway (surface colour).
6. **Annotation wins:** while the annotation still is up (`showsStill`, `:190`), covering does nothing extra.
7. **Not covered (existing gap, follow-up):** Settings dialog, command palette, menus that do not reach the pane.
