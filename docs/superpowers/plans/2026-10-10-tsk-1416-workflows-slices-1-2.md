# Workflow slices 1 and 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Assembly sessions message one another through real provider tools, then run and inspect a YAML workflow with deterministic checks and safe review loops on This Mac or Workbox Test.

**Architecture:** Slice 1 uses the existing SQLite broker and conversation manager, replacing group-based delivery with an owned-ID queue and exposing a single loopback endpoint through a small `assembly` MCP stdio client. Slice 2 extends the existing workflow engine and orchestration ledger; a run and its workers execute entirely on its owning backend. The existing Agents-panel run list remains the only run UI until slice 3.

**Tech Stack:** Rust, SQLite/rusqlite, Tauri 2, ACP, MCP stdio, the existing Codex bridge, YAML, Svelte 5.

**Spec:** `docs/superpowers/specs/2026-10-10-workflows-orchestration-design.md` (owner decisions D1–D13 are fixed). Task: [TSK-1416](https://app.notion.com/p/3f5394b0689d81e5b2aef3bb8bddfea8).

## Global constraints and execution rules

- This plan implements **only slices 1 and 2** of spec §9. A slice is one PR, and each task is a green review/commit boundary. Do not start slice 2 until slice 1 proof passes.
- KISS/YAGNI: smallest diff that passes the named behavior. Do not add an interface, configuration switch, compatibility path, speculative extension, or adjacent refactor. Reuse `workflow.rs`, `orchestration_events`, `core/src/broker.rs`, and the conversation manager. Delete the old group-routing path as the owned-ID path lands.
- Workers use subscription-authenticated CLIs; no API keys or API costs. MCP is available to Assembly sessions only. Token identity comes from the backend, never tool arguments or prompt text. Agent messages cannot approve anything.
- All database filters, joins, counts, ordering, and paging happen in **one SQL statement** per query, not after loading rows. Inspect the generated SQL/query in review; a correct in-memory result fails review.
- No UI regression tests. Do not write CSS `:has()` or Tailwind `has-[...]`. New frontend/tooling code is TypeScript; the existing `tools/codex-acp-bridge/bridge.mjs` may be edited in place, and any new probe is `.ts`.
- Tests that change chat must prove Claude Code and Codex on This Mac and on **Workbox Test** only (`ssh workbox-test`, `tools/workbox-test/README.md`). The Mac cases run in a Mac-local lane; the workbox lane never SSHes to the Mac to launch an app or server. Never attach a proof app to the owner's other saved machines. Agent browsers are headless, 1710×990, verified before use; stop the exact session and process tree. Stop task-owned app, Vite, API and Xvfb processes when done. Use no `dotnet watch`.
- Before each commit run `git status --short` and read the exact staged diff. Commit body includes `Task: TSK-1416 https://app.notion.com/p/3f5394b0689d81e5b2aef3bb8bddfea8`, ends `Committed-by: Codex`, has no co-author trailer. Any implementation commit that changes the documented architecture also updates `main-architecture-explained.html` in that commit and adds a section-01 change-log row; otherwise include `Architecture: unchanged`.
- Each task's named `cargo test` or Node command is its focused red/green check. At its end also run the relevant slice gate: `cd tauri-svelte-preview && npx tsc --noEmit && pnpm run check:svelte` (last line: `Files the /next shell owns: 0 error(s)`) and `cd core && cargo test`. Set `MSBUILDDISABLENODEREUSE=1` for heavy jobs. Do not run overlapping builds in one worktree. A green task has no broken compile or gate.
- For each implementation task: (1) add the named failing test or executable contract probe, (2) run its exact command and record the expected failure, (3) make the stated smallest edit, (4) rerun it and the gates, (5) inspect status and diff, then commit. Tests must assert data/behavior, never component structure. If a named probe is impossible on the installed adapter, record its exact error and take the stated fallback before continuing.
