# v2 Base Implementation Plan — Codex-shaped frame + rail correctness (TSK-759, TSK-762)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reshape `/next` into the Codex-app form — left Paneview (Sessions grouped by project / Files / Source control / Worktrees), conversation-only center with a display group beside it — and fix the three rail-correctness gaps that currently make the editor untestable (helper sessions in the rail, file-click not surfacing the editor, session pick not loading the project/worktree).

**Architecture:** The Gridview regions stay. The LEFT region's content becomes a dockview **Paneview** (collapsible accordion — the one dockview flavor not yet mounted; its `createComponent` returns a plain `IPanePart` object, no subclassing). The CENTER Dockview gets a two-group default layout: group A = Session (the conversation), group B = Editor + Browser — native drag/stack between groups gives "display panels start right, drag to center". Git moves from a center tab into a left pane. All content keeps the parking-stage teleport contract.

**Tech Stack:** Svelte 5, dockview-core 6.6.1 (`createPaneview` added to the existing Gridview+Dockview), existing lane services untouched.

**Feedback source:** `docs/superpowers/notes/2026-07-28-shell-v2-feedback.md`.

## Global Constraints

- **Old shell frozen**: `src/routes/+page.svelte` read-only; it carries an uncommitted user diff — never stage, commit, or revert it. `.vscode/` stays untracked. Old `$lib` reuse only after the poison audit (`docs/superpowers/notes/2026-07-28-old-shell-autopsy.md`).
- **No `src-tauri/` edits** (the dev watch is live; a rebuild kills the user's PTYs). `core/` IS safe — it is outside the watch (Task 1 relies on this).
- **Terminal DOM is sacred**: teleports move nodes; nothing destroys or clones an xterm host; the Session panel's snippet, refit path, and exclusion from panel loaders stay byte-identical.

- Commits: plain messages, **no Co-Authored-By trailer**. Tests: node scripts (`node --experimental-strip-types scripts/<x>.test.mjs`) registered as `test:*` in `tauri-svelte-preview/package.json`.
- Plain English in user-visible strings. Palette: bg `#101014`, raised `#17171d`, border `#22222c`, text `#d8d8e0`, muted `#6d6d7d`, faint `#4c4c5a`.
- Layout persistence: `mac-command-bar.next.*` keys, quota-safe, guarded restore (panel-set equality + try/catch + clear-and-rebuild), reentrancy guard released on a macrotask (the pattern already in `frame.ts`/`centerDock.ts` — copy it, do not invent a new one).
- dockview 6.6.1 facts (verified against installed typings): `PaneviewFrameworkOptions.createComponent: (options) => IPanePart` where `IPanePart = { element, init(parameters), update(params), dispose() }` (`paneview/paneviewPanel.d.ts:24-28`); `PaneviewApi.addPanel(AddPaneviewComponentOptions)` (`api/component.api.d.ts:198`); Paneview headers are built-in (title in addPanel), `createHeaderComponent` optional — do NOT build custom headers this slice. import type { OwnedSession } from './ownedSessions';
```ts
import type { AgentSession } from '$lib/tauriSource';

export interface SessionGroup<T> {
  /** Project folder name, e.g. "mac-command-bar"; "Other" when no path is known. */
  name: string;
  /** Full path used as the stable group key ('' for Other). */
  path: string;
  items: T[];
}

function projectOf(path: string | null | undefined): { name: string; path: string } {
  const trimmed = (path ?? '').trim();
  if (!trimmed) return { name: 'Other', path: '' };
  const parts = trimmed.split('/').filter(Boolean);
  return { name: parts[parts.length - 1] ?? trimmed, path: trimmed };
}

function matches(query: string, ...fields: Array<string | null | undefined>): boolean {
  const needle = query.trim().toLowerCase();
  if (!needle) return true;
  return fields.some((field) => (field ?? '').toLowerCase().includes(needle));
}

/** Group + filter the rail's two lists. Groups sort by most items first, "Other" last;
 * items keep their incoming order (the stores already order by recency). */
export function groupSessions(
  owned: OwnedSession[],
  available: AgentSession[],
  query: string
): { owned: SessionGroup<OwnedSession>[]; available: SessionGroup<AgentSession>[] } {
  const groupBy = <T>(items: T[], pathOf: (item: T) => string | null | undefined, hit: (item: T) => boolean) => {
    const groups = new Map<string, SessionGroup<T>>();
    for (const item of items) {
      if (!hit(item)) continue;
      const { name, path } = projectOf(pathOf(item));
      const existing = groups.get(path) ?? { name, path, items: [] };
      existing.items.push(item);
      groups.set(path, existing);
    }
    return [...groups.values()].sort((a, b) =>
      a.path === '' ? 1 : b.path === '' ? -1 : b.items.length - a.items.length
    );
  };
  return {
    owned: groupBy(owned, (s) => s.projectPath ?? s.cwd, (s) => matches(query, s.title, s.projectPath, s.cwd)),
    available: groupBy(available, (s) => s.projectPath, (s) => matches(query, s.title, s.projectPath, s.description))
  };
}
```
