Three owner decisions

  1. Home machine. Recommended: Workbox default; require explicit configuration when unavailable, without silently creating a local replacement. Test only against Workbox Test.
  2. Standing merge authorization. Recommended: explicitly ratify D6's narrow engine-only exception for approved pipeline runs with I'll merge off. Other agents, controllers and slice PRs still require specific owner merge requests.
  3. Proof attachment. Recommended: GitHub release assets on a dedicated workflow-proof-<run-id>-<proof-attempt> tag, with stable URLs and digests in the ledger, PR and task. Final review runs after proof publication/PR and concerns the exact current head. No local-path-only attachment or screenshot binaries on main.

One source and one authority for each job.

YAML files define workflows; the owning backend's ledger records runs. The engine runs checks and applies rules. One home session supervises. Only owner buttons answer decisions. SQL selects bounded data; the desktop does not become a second engine.

No visual editor, phone API, fan-out, backend-to-backend networking, compatibility template path or speculative framework. No UI structure tests or CSS relational selectors. Future implementation checks in the Markdown are requirements, not results claimed by this docs lane.
