Parallel execution

How implementation agents run concurrently

The plan freezes shared contracts first, then uses a rolling queue of at most six file-independent implementation agents. Luna Max handles detailed, straightforward packets; SOL-medium takes the Roslyn lifecycle decision and every milestone code review.

Gate A · sequential foundation

No feature agent starts until this controller-owned sequence is stable.

  1. Reconcile the shipped baseline and native proof.
  2. Run the extension/API comparison and stop for the user's selection.
  3. Land contrast tokens and shared primitives.
  4. Rebrand the public app and artifacts to Assembly while preserving compatibility state.
  5. Restore Settings and freeze shell, roster, minimize, and quick-open contracts.
  6. Commit the controller-owned interfaces.

Concurrency guardrails

  • Maximum six implementation agents; an optional seventh slot is read-only only.
  • Maximum two simultaneous heavy build/test runners; never a third.
  • Every agent receives an exact file allow-list; only the controller edits shared seams.
  • Native certification and milestone SOL-medium reviews are serialized.
  • Any data lane must execute filtering, joining, grouping, sorting, aggregation, and paging DB-side in one translated statement or a database view, with generated SQL inspected.

Round B1 · six independent implementation slots

These exact packets can begin together after Gate A. A heavy token is held only while its focused build or test command runs.

1 · SessionsLifecycle, rail store, metadata, notifications · Luna Max · Node-light
2 · Editor and runEditor helpers, configurations, formatting, Problems · Luna Max · Node-focused
3 · Local GitGit graph, explorer, worktrees, named Rust modules · Luna Max · heavy token 1 only when needed
4 · Hosted GitHubPR queue/detail/review/budgets and named GitHub Rust module · Luna Max · heavy token 2 only when needed
5 · MarkdownMarkdown model, component, fixtures, and tests · Luna Max · Node-light
6 · Conversation UIFrontend packets A–D first; Rust parser waits in B2 · Luna Max · Node-light initially

Round B2 · rolling native queue

Finished slots are reused only after ownership and dependency checks.

  1. Conversation Rust parser and attachments take the first released heavy token.
  2. Browser and the app-global floating fan take one token when the shell contract is free.
  3. Resource model/UI preparation may run beside Browser.
  4. SOL-medium runs Roslyn registry consolidation alone after the required baselines.

Milestone C · dependent integration

  • The controller applies shared-seam receipts once, after parallel agents return.
  • Integrated Agent begins only after sessions, GitHub, resources, Browser annotations, and conversation authority are certified.
  • A selected extension adapter may run beside Integrated Agent because its owned paths do not overlap.
  • The database console remains conditional and requires DB-side query/view design plus generated-SQL review.
