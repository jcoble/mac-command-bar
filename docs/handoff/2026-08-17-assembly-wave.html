Read this before touching anything

Two architecture facts that have been re-derived, wrongly, more than once.

1. The SQLite database is the source of truth and the event source

Everything bases off it. Sessions, events, attachments, annotations and drafts all live in sessions.db at ~/Library/Application Support/dev.blackcolours.MacCommandBarWebviewPreview/. The conversation transcript is not a cache of something else — the event journal in that database is the conversation. If a value is not in the database, it is not real, and a UI that shows something the database does not contain is a bug.

Practical consequence: never add a code path that reconstructs session state from anywhere else. When the transcript looks wrong, read the rows first and confirm what the database actually holds before changing rendering code.

2. localStorage holds VIEW state, and that is deliberate — do not "fix" it

The /next shell keeps nineteen n.* keys in localStorage. It is tempting to read that as the database being duplicated. It is not. Every one of them stores something the database has no representation of, and each has a reason written into its own module header:

  • n.session-workspaces — what each session had open: editor tabs, file tree, scroll positions. It exists because the editor and file tree are one-of-each for the whole shell, so two sessions in the same repository shared one set of tabs and lost your place both ways. Its second half is explicitly a performance decision: the last few sessions' tabs are held in memory so switching back restores the files themselves instead of re-reading every one off disk (sessionWorkspaces.ts header).
  • n.rail-groups — which rail headings are open, and the grouping and filtering of the rail. "Nothing here decides what a session IS" (sessionGroups.ts header).
  • n.stacks.definitions, n.stacks.runs — saved run configurations such as pnpm dev or docker compose up. A separate feature with its own user data, whose stated rule is "No backend, ever. The only IO here is localStorage." The keys still say "stack" deliberately: renaming them would make users' saved configurations come back empty after an update (stackStore.svelte.ts header).
  • n.center-tab-v1, n.right-tab-v1 — which tab each session was left on, keyed by session id (workbenchTabs.ts header).

The database stores no notion of "which tab you left this session on", so none of this is a second copy of anything. Disconnecting it would not simplify the app; it would lose the state and the switch-cost work that was done on purpose.

The one key that genuinely did duplicate database truth is already gone. mac-command-bar.next.owned-sessions re-imported sessions on every launch whenever the database was empty, which is what made repeated database wipes appear not to work. The whole adoption block was deleted in 65c2353. It is a different key from the nineteen above and it no longer exists.

Still worth knowing when resetting state: WebKit writes localStorage lazily, so a removeItem followed by killing the app discards the removal. That cost hours before it was understood.

Standing rules

Every one of these was set by the owner and holds until they lift it. Paste them into every dispatch.

  • ✕No CSS :has(), ever — including Tailwind has-[...] variants. Profiling found the WebKit main thread spending seconds in :has() invalidation during transcript DOM insertion; once any such rule is registered it is re-checked on every DOM mutation in the document. Purged in ccd3cc1. Use a state class where the state originates.
  • ✕No UI regression tests until the owner says otherwise. Thirty-eight were deleted on 2026-08-17. Tests for logic and data are still expected.
  • ✕No git reset --hard. It once destroyed ~44 files of unstaged work. Use git reset --soft HEAD~1, git restore -- <path>, git revert, or git stash push -m.
  • ✕No Co-Authored-By trailer in any commit. Every message ends Committed-by: Claude.
  • ✕Never invoke the claude-api skill — it inlines ~328K tokens. Read the one relevant doc file instead.
  • →Tokens only for anything visual. Every colour, radius, spacing step, border and shadow comes from nextTokens.css and themeRegistry.ts. No raw hex or one-off rgba() in components. Adding a missing token is expected work, not scope creep. Verify in Dracula as well as the default theme.
  • →Browser testing is headless at 1710×990, verified with an innerWidth eval before any screenshot. In Playwright configs the viewport goes inside use, after any ...devices[...] spread, which otherwise silently drops it to 1280×720.
  • →Every animation must end. No idle loops, no perpetual transitions. Animate transform and opacity only. Performance is why this app exists.
  • →Transcript text stays small and dense. Action icons get bigger; message text does not.
  • →Never swarm builds. Two or three concurrent cargo/dotnet builds maximum, and lanes touching the same project are sequenced regardless of count.
  • →Delete worktrees immediately once merged or abandoned. Fifty stale ones once filled the disk.
  • →All SQL runs server-side. A correct value computed in memory is still a defect.

How to dispatch, so this stops happening

Committed as b5a03c0 to CLAUDE.md and AGENTS.md.

A sub-agent starts cold. It cannot see the conversation, the owner's messages, or any image the owner pasted — pasted images live in the controller's context, not on the agent's disk. Whatever the controller retypes from memory is the entire world the agent gets, and a paraphrase silently drops requirements.

So every dispatch hands over the artifacts that already hold the decisions:

  1. The Notion task id, with instructions to fetch it and read the relevant sections verbatim. The task is where the owner's decisions accumulate in their own words, including corrections the controller has forgotten.
  2. Absolute paths to the reference screenshots, with instructions to read each one before touching a file. Durable copies live under ~/dev/work/reports/; the session image cache at ~/.claude/image-cache/<session>/ is evicted and cannot be relied on.
  3. A required reply before any edit — a requirement-by-requirement checklist marked done, will fix, or blocked. A misread then surfaces in one message instead of in a diff the owner has to catch by eye.

Corrections go to the same agent via SendMessage when the fix depends on what it already built. A fresh agent re-reads everything and repeats the mistakes it cannot see.

The spec itself names exact files with line anchors, the contract, the failing test, the verbatim verification command, a "done means" checklist, and the expected diff size. If the diff size cannot be estimated, the task is not understood yet — do not dispatch.

Traps

Each of these cost real time. None are obvious from reading the code.

The adapter process only runs during a turn

By design, and the owner is emphatic about it: the ACP adapter starts for the length of a turn and stops immediately after, because the process tree retains hundreds of megabytes between turns. Capabilities are persisted in extra_json and read back, so no adapter is needed between turns. A session being "not running" is normal, not a fault to fix.

WebKit writes localStorage lazily

A removeItem followed by killing the app discards the removal entirely. Three separate "sequencing" explanations for this were wrong before the real cause was found. The legacy adoption block that re-imported sessions on every launch was deleted outright in 65c2353.

The error strip paints behind the panes

It was positioned absolute with no z-index, and each pane forms its own stacking context, so errors were invisible. Now fixed with z-[70] in ShellOverlays.svelte:145-153. It only renders while centerTab === 'session'.

Transcript import has three separate ways to write a broken row

All three were hit in sequence. Import must insert a live overlay or list_sessions fails on the row it just created; extra_json must be complete or start-up panics with missing field 'generation'; and events must be written as a whole AgentConversationEvent, not a bare payload, or decoding fails with invalid number at line 1 column 125.

Transcript extension uses negative sequence numbers

Older records are stored with negative sequences so existing nonnegative ones stay untouched (30ce778). Code that assumes sequences start at zero will be wrong.

The ensure_inner early return is load-bearing

Changing it broke two tests covering suspend/resume generation handling. The correct narrow fix was adding current.generation > 0 && so a never-run imported session falls through and starts once. Do not widen it.

command -v codex returns alias text, not a path

Five dispatch lanes died instantly because of it. The real binary is /Users/blackcolours/.nvm/versions/node/v24.12.0/bin/codex. Also on macOS: no timeout or gtimeout, and rg --include is not a flag — use -g '*.ext'.

The transcript performance win was not the two-pass split

It came from building into a plain object, which avoids thousands of reactive-proxy invalidations, plus the id-index merge. Splitting the work into two passes did not itself make anything faster, and describing it that way is wrong.

provider.rs is dead code

The old direct runner survives as a file but is not declared by mod.rs since the ACP cutover (beb5967). Reading it will mislead you.
